This page shows you how to let an AI agent on your Mac search, read and edit your notebooks through Penmoss's MCP server. One server reaches every notebook on your Mac. Pick your agent in the tabs; the choice holds for the whole page.

You need Penmoss on your Mac with your notebooks added, and the agent installed: [Claude Code](https://docs.claude.com/en/docs/claude-code/overview), the [Codex CLI](https://github.com/openai/codex), [OpenCode](https://opencode.ai), or any client that runs local MCP servers, such as the Claude desktop app or Cursor.

## Connect it

In Penmoss, open **Settings → Agents**. **The MCP Server** shows how to add the server to each agent, with **Copy** buttons. You add it once per agent, and it covers every notebook. You don't name the agent: each edit is named in History by the app and session that made it, such as **Claude Code · 7736c5e9**.

<Tabs syncKey="agent">
<TabItem label="Claude Code">

Under **Claude Code: run in a terminal**, choose **Copy**, then paste the command into Terminal and run it. It looks like this:

```sh
claude mcp add penmoss -- '/Applications/Penmoss.app/Contents/Helpers/Penmoss CLI.app/Contents/MacOS/Penmoss' --penmoss-cli mcp
```

This adds the server for the folder you run it in. To have it in every project, add `--scope user` after `add`.

Start a new Claude Code session in that folder. Run `/mcp` to check that `penmoss` is connected. Then ask, for example: "Search my Penmoss notes for the garden plan and add today's watering to it."

</TabItem>
<TabItem label="Codex">

Under **Codex: add to ~/.codex/config.toml**, choose **Copy**, and paste the lines at the end of `~/.codex/config.toml` (make the file if it does not exist). They look like this:

```toml
[mcp_servers."penmoss"]
command = "/Applications/Penmoss.app/Contents/Helpers/Penmoss CLI.app/Contents/MacOS/Penmoss"
args = ["--penmoss-cli", "mcp"]
```

Start a new Codex session. Run `/mcp` to check that the Penmoss tools are there. Then ask, for example: "Find my Penmoss note about the release checklist and tick off the first item."

</TabItem>
<TabItem label="OpenCode">

Add the server to OpenCode's configuration: `~/.config/opencode/opencode.json` for every project, or `opencode.json` in one project:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "penmoss": {
      "type": "local",
      "command": [
        "/Applications/Penmoss.app/Contents/Helpers/Penmoss CLI.app/Contents/MacOS/Penmoss",
        "--penmoss-cli",
        "mcp"
      ],
      "enabled": true
    }
  }
}
```

If the file already has an `mcp` section, add the `penmoss` entry to it. Penmoss's settings show ready-made lines for Claude Code and Codex only; for OpenCode the command is the same as Codex's.

Start OpenCode again, so it reads the new configuration. Then ask, for example: "Append a summary of this session to today's note in Penmoss."

</TabItem>
<TabItem label="Other MCP clients">

Penmoss's MCP server is a local server over stdio: the client starts it as a program and talks to it on its standard input and output. Give the client this program and these arguments:

- **Command:** `/Applications/Penmoss.app/Contents/Helpers/Penmoss CLI.app/Contents/MacOS/Penmoss`
- **Arguments:** `--penmoss-cli`, `mcp`

If you have [installed the `penmoss` command](/docs/reference/cli/#install), the command can be `penmoss` and the argument `mcp`.

Many clients, such as the Claude desktop app (`~/Library/Application Support/Claude/claude_desktop_config.json`) and Cursor (`.cursor/mcp.json`), take a JSON file in this shape:

```json
{
  "mcpServers": {
    "penmoss": {
      "command": "/Applications/Penmoss.app/Contents/Helpers/Penmoss CLI.app/Contents/MacOS/Penmoss",
      "args": ["--penmoss-cli", "mcp"]
    }
  }
}
```

Restart the client after you change it.

</TabItem>
</Tabs>

### Agents connected by name before

Earlier versions of Penmoss gave each agent its own copy of a notebook and its own server, such as `penmoss-notes-claude-code`. Those keep working. In **Settings → Agents**, open the notebook to see them, marked as older copies, and choose **Remove** once the agent uses the one server. Remove it from the agent too: `claude mcp remove penmoss-notes-claude-code`, or delete its lines from `config.toml`. If the copy has changes it hasn't pushed, Penmoss says so before removing it.

## Receive comments from your notes

Claude Code can also receive the [comments](/docs/comments/) you send it from a note, read the thread, edit the note and reply. This uses Claude Code's channels, a research preview.

1. In **Settings → Agents**, under **The MCP Server**, turn on **Receive comments sent to Claude Code sessions**.
2. Copy and run the new **Claude Code: run in a terminal** command, which adds `--channel`. If you added the server before, run `claude mcp remove penmoss` first.
3. Start Claude Code with the command under **Then start Claude Code with its channel**:

   ```sh
   claude --dangerously-load-development-channels server:penmoss
   ```

Now **Send to** offers the session in every notebook, and a thread you send to it arrives naming its notebook. See [Comments to agents](/docs/agents/comments/).

## With the CLI instead

An agent that runs shell commands can also use the [`penmoss` command](/docs/reference/cli/). [Install the command](/docs/reference/cli/#install), then tell the agent how to use it in your project's `CLAUDE.md` or `AGENTS.md`: see [Agents and the CLI](/docs/reference/cli/#agents-and-the-cli) for a block to paste.

- **Claude Code:** allow the commands, so it does not ask each time: add `Bash(penmoss:*)` to `permissions.allow` in `.claude/settings.json`.
- **Codex** runs shell commands in a sandbox. The CLI writes to `~/.penmoss` and reaches your repository's host, so allow both in Codex's sandbox settings, or use the MCP server above.

## What the server offers

- **Tools only.** It has the [35 tools](/docs/reference/mcp/) and no resources or prompts.
- **Every notebook, one server.** A note's id finds its notebook; searches and lists cover every notebook; a new note takes `notebook`, its name, when there are several. See [More than one notebook](/docs/reference/mcp/#more-than-one-notebook).
- **Instructions.** The server tells the client how to use its tools: search first, pass `baseVersion` to edits, and read again after a conflict.
- **MCP versions** from 2024-11-05 to 2025-11-25.

## If it does not work

- **The agent shows no Penmoss tools, or says the server failed.** Run the server's command with its arguments in Terminal by itself. It should wait quietly for input; ⌃C stops it. If it prints an error, fix that first. `penmoss notebook ls` lists the notebooks and copies on this Mac.
- **Claude Code: the server is missing.** `claude mcp list` shows what Claude Code has, for this folder. Add it again with `--scope user` to have it everywhere.
- **Codex or OpenCode: no Penmoss tools.** Check that `config.toml` or `opencode.json` has the lines exactly as copied (valid TOML or JSON), and start a new session.
- **Its edits do not show in the app.** The server pushes a minute after edits settle. Choose **Sync Now** in the app to pull them at once.
