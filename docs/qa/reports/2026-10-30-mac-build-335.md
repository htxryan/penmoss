## Findings

### F1 [blocker → fixed in PR #169] Build 335: the menu bar takes no clicks (the app runs as a UIElement)

- **Steps to reproduce:** install build 335 on macOS 26.6.2 and launch it. Click any menu-bar title while Penmoss is in front.
- **Expected:** the menus open, and Penmoss has a Dock icon.
- **Actual:** the titles draw in black but don't open. `lsappinfo info -only ApplicationType` gives `UIElement`. `tell application "Penmoss" to activate` leaves another app in front. There is no Dock icon. It happens on every launch, with or without a debug port.
- **Cause:** `apps/desktop/src/main.ts:565` (from T29) calls `setVisibleOnAllWorkspaces(true, { visibleOnFullScreen: true })` without `skipTransformProcessType`, so Electron hides the Dock icon for good.
- **Fix:** PR #169 makes the capture window an NSPanel and passes `skipTransformProcessType`. Tested: Foreground; a real CGEvent click opens the menus; Quick capture shows over full-screen TextEdit and takes typing.
- **Caveat:** AppKit logs "NSWindow does not support nonactivating panel styleMask" twice per launch (commented on the PR).

### F2 [should-fix] History sometimes says "could not read … git history" (`config.lock` race)

- **Steps to reproduce:** open Version history (⌘⌥⇧H) on a git note while a sync may be running (soon after launch, or after Sync now). It happened 2 of about 4 times.
- **Expected:** the version list.
- **Actual:** "Version history could not read Mac check's git history." Try again worked.
- **Evidence:** the page console during a retry showed `[git] git sync failed GitTransportError: git failed. (git config exited 255: error: could not lock config file …/git-notebooks/01M67D7REH1S5MPXQNHA0KNCNR/repo.git/config: File exists)`. Raw `git.op('log')` calls succeed in about 200 ms.
- **Suspect:** `NodeTransport.init()` (`packages/git-notebook/src/node/transport.ts:106-142`) writes about 20 `git config` keys each time it's called, so two overlapping git operations on one clone collide on `config.lock`. Syncs can fail the same way.

### F3 [should-fix] The Mac app reads git's identity only at launch

- **Steps to reproduce:** add a notebook while `user.email` is a private address and the push is refused (GH007). Change `git config --global user.email`, then Sync now.
- **Expected:** the next sync uses the new identity.
- **Actual:** Settings still said "Commits as … <ryan@example.invalid>" and the push was refused again. After a relaunch the identity updated, and the stuck commit was rebuilt and pushed. Branch `eb0ae69` is authored by the no-reply address, and there's no gmail commit on it.

### F4 [should-fix] Add asks for Touch ID before telling you a rewritten remote can't be used

- **Steps to reproduce:** run `git config --global url.git@github.com:.insteadOf https://github.com/`, then in Settings Add `https://github.com/htxryan/penmoss-git-notebook-scratch.git` on a new branch.
- **Expected (desktop.md §6):** "Add is refused", with the message naming the SSH remote, before anything else.
- **Actual:** the usual "confirm private with Touch ID" notice. The refusal can only come after the person confirms. The existing notebook's sync and the CLI add are refused correctly, with the SSH remote named (CLI exit 1, where the docs' table suggests 7: nit).

### F5 [should-fix] Most git-notebook actions exist only in Settings

- **Steps to reproduce:** search the palette for git, notebook, sync, private, token, remove, push, pull and sign, and look through the File and View menus.
- **Expected (brief F2 / D34):** each Settings action can also be run from the palette or a menu.
- **Actual:** only "Git notebooks" (opens Settings) and, for a git note, "Save a version of this note now" (which is Sync now). Missing from the palette and menus: Confirm private, Remove from this Mac, Use/Forget token, Push after, Pull every, Sign commits, and Confirm Delete for good again.

### F6 [should-fix] GH007 (private email) blocks every push, with no help in Penmoss

- **Steps to reproduce:** set your GitHub email to private with "Block command line pushes that expose my email", keep a private `user.email` in git, add a notebook.
- **Actual:** "Sync stopped". The error quotes GitHub's GH007 text. Settings shows "Commits as Ryan Henderson <ryan@example.invalid>" with no warning at Add, and a notebook has no identity of its own.
- **Suggestion:** detect GH007 and suggest the `users.noreply.github.com` address, or a per-notebook identity.

### F7 [nit] Manual check step 4 (desktop.md §6) is refused as written

- `penmoss notebook add https://github.com/htxryan/penmoss-git-notebook-scratch.git --branch … --name check` exits 7: "needs a GitHub token". The step should say to pass a token (`PENMOSS_GIT_TOKEN` or `--token -`) or `--confirm-private`.

### F8 [nit] The 2.5 s sync at quit never pushed

- In A5 (note window, ⌘W, quit) and C4 (⌘Q within 160 ms of typing), no commit reached the branch at quit. Both were pushed 18–20 s after the next launch. Nothing was lost.
- On this Mac a sync (fetch plus push) takes longer than 2.5 s, so the quit-time sync may never push here. Manual step 5 reads as if `penmoss cat` shows the typing straight away.

### F9 [nit] The section says "Synced · 1 waiting" for about 70 s with the network down

- Wi-Fi went off at 17:17:50 and the edit was made at :58. The section showed "Synced · 1 waiting" until 17:19:03, then "Offline · 1 waiting": the first push attempt came at Push after = 60 s.
- After the network returned at 17:19:26, it stayed "Offline" until 17:20:24 (backoff), then synced.
- Evidence: `offline1/watch.jsonl`, `offline1/steps.log`.

### F10 [nit] The CLI can't change a git note's title

- `penmoss edit <id> --replace 'From the CLI' --with '…'` fails with exit 4, "The text to replace is not in the note", including with `--scope markdown`. `rename` is for folders only.
- The local MCP's `set_properties` can, and that's what C2 used.

### F11 [nit] Bidi control characters survive in file names and the Trash toast

- A note titled `x] (git history keeps it) in the git notebook at github.com/evil [ ‮אבג…` is written to the branch as `x (git history keeps it) in the git notebook at github.com evil ‮אבגדהוזחטיכלמנס.md`. The brackets and `/` are stripped, but U+202E (RLO) is kept, so the name can display reversed in GitHub's or a terminal's file listings.
- The Trash toast also shows the raw title, RLO included.

### F12 [nit] A desktop unit test times out on this Mac

- `apps/desktop` `git-notebooks.test.ts › runs the engine's calls: commit, push, list, read and log` fails at the default 5 s timeout, on `main` too: git on this Mac is slower. The e2e suite already allows 30 s.
