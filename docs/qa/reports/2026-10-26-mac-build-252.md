# Penmoss Mac QA, 2026-10-26, build 252

## Summary

Build 252 (0.1.0) on macOS 26.6.2, run by Claude Code through computer use (System Events assistive access is refused on this Mac). Finished 2026-10-26, about 8:45 PM CT.

**69 checks: 46 Pass, 21 Partial, 2 Skipped (M5, M9), 0 Fail.** Most Partials are steps I couldn't run under the ground rules (Touch ID, emoji picker, saving quick capture or opening Today, which would write outside the QA folder). The rest carry one of the bugs below.

**13 bugs; fix these 5 first:**

- **B11**: Quick open launched from the command palette has no focus, so typing goes into the note behind it.
- **B12**: `penmoss://note/<unknown id>` creates an empty note with that id.
- **B10**: restoring a note can put it at the top level instead of back in its folder (1 of 2 times).
- **B4**: Escape throws away a math formula you just typed.
- **B5**: the Markdown source view didn't take typing; needs a human check.

The rest are minor or cosmetic: B1 ⌘/, B2 window title, B3 table paste, B6 image Markdown, B7 clipped tree notices, B8/B9 live Trash row, B13 the last note doesn't reopen.

**What works well:** sync and live agent edits, search (exact and by meaning, with a clean empty state), the command palette, the graph, version history, every editor shortcut, both copy formats, themes in light and dark, settings that sync, the compact layout down to 480×360, and keyboard focus, which stays visible everywhere. Idle memory is about 706 MB across 5 processes at 0.5% CPU. Fast typing peaks at about 69% CPU and drops back within 2 s.

**Cleanup:** every setting is back as recorded (theme, mode, full width, sidebar, Display, shortcuts; checked through `get_settings`). The window is back at 1515×1109 pt. The QA folder, its subfolders and all 7 QA notes (including two stray top-level notes from New note and the B12 phantom, which I moved into the QA folder first) are in Trash, not deleted for good. Nothing I created is left in the tree. I wrote nothing to Ryan's notes, Journal or Assistant Memory. I briefly opened 2026-W44, 2026-10-24 and one Assistant Memory note, but only to read them. The stray "x" from B11 landed in my own N3 and was removed.

## Bugs

### B1 ⌘/ doesn't open the Keyboard shortcuts list (severity: minor)

Steps: Penmoss frontmost (⌘K works in the same state), press ⌘/. Expected: the Keyboard shortcuts dialog, as the list and palette advertise. Actual: nothing happens; the dialog opens fine from the palette. Screenshot: Q9-shortcuts.png. Repeats: 3 of 3. Caveat: another app's global hotkey could be taking ⌘/ on this Mac (Wispr Flow is running).

### B2 Window title doesn't follow the open note (severity: cosmetic)

Steps: open or rename a note. Expected: the macOS window title shows the note title. Actual: the window title is always "Penmoss" (CGWindow name), so Mission Control and the Window menu can't tell notes apart. Repeats: 2 of 2.

### B3 Pasting tab-separated text into a table doesn't fill cells (severity: minor)

Steps: in a table cell, paste `r1c1\tr1c2\tr1c3` × 3 lines (pbcopy). Expected: a 3×3 grid of cells filled (or new rows/columns). Actual: all nine values land in the one cell as three lines of text joined by spaces; the column also widens. Screenshot: E4-table-paste.png. Repeats: 1 of 1.

### B4 Escape discards a math formula you just typed (severity: major)

Steps: insert a Math block (`/math`), type `e^{i\pi}+1=0` (the preview renders it), press Escape. Expected: the formula is kept, as when you click out of the block (which does keep it) and as the Mermaid block does. Actual: the block goes back to "Empty formula: click to edit" and the server stores an empty `$$\n$$`. Repeats: 3 of 3. Clicking outside commits correctly.

### B5 Can't type in the Markdown source view (severity: major, needs a human check)

Steps: in "Editor torture", ⌘⇧M, click a line in the source, type. Expected: the text appears and the rich view updates. Actual: the source box gets a focus ring but shows no caret and ignores typing (3 tries, Penmoss frontmost); nothing reached the server. Repeats: 3 of 3. Caveat: my typing works everywhere else in the app, but please confirm by hand in case the source view is read-only by design.

### B6 Image Markdown can't be entered in the editor (severity: minor)

Steps: in a note, type `![x](https://upload.wikimedia.org/wikipedia/commons/a/a9/Example.jpg)` and press Enter; separately, paste the same text. Expected: an image block (the slash menu has Image, but only for uploads). Actual: typed, it stays as literal text; pasted, it becomes a link `[x](…)`, losing the `!`. The same Markdown sent through MCP renders the image fine. Repeats: 1 of 1 each.

### B7 Loop-refusal notice is clipped (severity: cosmetic)

Steps: drag folder B onto its own subfolder A2x. Expected: a readable notice. Actual: the notice sits at the bottom of the tree pane, cut off after "A folder cannot move into itself or". Screenshot: F2-loop-refused.png. Repeats: 1 of 1.

### B8 A Trash row that arrives live lacks the agent attribution (severity: minor)

Steps: leave the app's Trash view open, then `trash_note` a QA note via MCP. Expected: "by Claude Code ✦" on the new row. Actual: "Deleted Oct 26, 2026 from B · 31 days left", no attribution. When I opened Trash fresh after another `trash_note` (N1), the row did read "by Claude Code ✦ from A · 30 days left", so the live-inserted row seems to be built from incomplete data. Screenshot: F8-trash-agent.png vs F10-delete-confirm.png. Repeats: 1 of 1 live, 0 of 1 fresh.

### B9 Live Trash row says "31 days left" (severity: cosmetic)

Steps: same as B8. Expected: 30 days left. Actual: 31 days left on the live row; a freshly loaded row deleted 2 minutes later says 30. Repeats: 1 of 1.

### B10 Restoring a note puts it at the top level instead of its folder (severity: major)

Steps: delete folder B in the app, restore B from Trash, then `trash_note` N8 (which was in B; the tool returned B's id as its folder), then Restore N8 in the app's Trash. Expected: N8 back in "QA Mac…/B" (the row said "from B", and B exists with the same id). Actual: N8 at the top level, both in the app and in `list_folder`. For a user this puts a note in the wrong place, outside the folder they were working in. Repeats: 1 of 2. Restoring N1 (trashed by MCP while Trash was closed, then restored from a freshly opened Trash) went back to A correctly, so this probably shares B8's cause: the row that arrived live while Trash was open.

### B11. Quick open from the palette leaves the keyboard in the note behind it (Major)

Steps: open a note, press ⌘K, type "Quick open", press Return.
Expected: the Quick open dialog opens empty with the caret in its field.
Actual: the dialog opens pre-filled with the palette text ("No matches for "Quick open""), and its field has no focus. The next keystroke goes into the note behind the dialog: a typed "x" landed at the start of N3 Agent note. Escape doesn't close the dialog either, because focus is in the editor. ⌘A then selects the whole page. ⌘P on its own works correctly. Reproduced 2 of 2. I removed the stray "x" from N3 through MCP; no note outside the QA folder was changed.

### B12. A deep link with an unknown id creates an empty note with that id (Major)

Steps: `open "penmoss://note/01M5XXXXXXXXXXXXXXXXXXXXXX"` (no note has that id).
Expected: a "Note not found" message, with nothing created.
Actual: Penmoss shows an "Untitled" editor, Folder "Top level", Created "Unknown", "Saved · synced", with that id in the frontmatter. I typed nothing and left it, but `list_folder` then showed a new top-level note with that id and a null title. So any mistyped or stale link (for example to a note deleted for good) leaves a blank note in the tree, and accepts a caller-chosen id. I moved it into the QA folder for cleanup.

### B13. The last open note doesn't reopen after quitting (Minor)

Steps: open N8 Third note, ⌘Q, relaunch.
Expected (per the script): N8 reopens.
Actual: "No note open". 4 of 4 relaunches today (N7, N11 and twice in M4). Reopening the window after ⌘W also lands on the home screen rather than the last note. Returning from Settings with "← Notes" shows "No note open" too, which may be the same root cause.

## UX feedback

- Sidebar calendar: "SEPTEMBER 2026" wraps onto two lines, which pushes the month arrows and Today button out of line. The calendar's collapsed/expanded state also isn't obvious from the header.
- ⌘E on a quick tap jumps straight back to the previous note (like ⌘Tab). That's handy, but nothing on screen says so until you hold ⌘.
- With a fast burst of edits, one ⌘Z undid a link, a new line, typed text and a code block together. That may just be the typing-group window, but it can feel like lost work.
- The folder-delete notice overlaps the last tree row ("Moved "Q9f" to Trash…" printed over another label), as in B7.
- Leaving Settings with "← Notes" comes back to "No note open" rather than the note that was open. ⌘P from inside Settings works and goes straight to the note, so it's only the back link.
- Escape doesn't leave Settings.
- The quick-capture shortcut is ⌃⌥⌘N (the global field), but the in-app list shows Quick capture as ⌘⇧K. Two shortcuts for one feature with no explanation in the list.
- View menu shows "Toggle Full Screen" twice. Insert menu items all start with "Insert:" and none has a shortcut.
- "Sync on this device" sits in the File menu as a plain item with no state shown; it's easy to hit by mistake and unclear whether it turns sync on or off.
- Keyboard users have to Tab through every tag (two stops each, ~45 tags) to get from the tree to the editor. Make the tag list one stop with arrow keys inside it (like the tree), or add a "skip to editor" key. ↓ on the New folder button scrolls the tree rather than entering it.
