# ADR 0001: Monorepo and tooling

- Status: Accepted
- Date: 22 October 2026
- Task: T1 ([#1](https://github.com/htxryan/penmoss/issues/1))

## Context

Penmoss ships a web app, a Cloudflare Worker, an Electron app, an Android shell and a CLI that all share one schema, codec and editor (plan D5, D6). They need one repository, one set of commands and one quality gate, and the backend must start on the Workers Free plan (D20, D26).

## Decision

- **pnpm workspace** (`apps/*`, `packages/*`), pnpm pinned through `packageManager` and run through Corepack. Internal packages export their TypeScript source (`"exports": "./src/index.ts"`), so there is no build step between packages; Vite and Wrangler bundle them.
- **Exact pins.** `savePrefix: ''` makes every `pnpm add` exact. pnpm 12's default 24-hour `minimumReleaseAge` supply-chain gate stays on, and only `esbuild` and `workerd` may run install scripts (`allowBuilds`).
- **TypeScript strict** from `tsconfig.base.json` (plus `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`), one `tsconfig.json` per package, checked with `tsc --noEmit`.
- **ESLint flat config** with type-aware typescript-eslint, React Hooks and React Refresh rules, `no-restricted-exports` for the plan's named-exports rule, and Prettier for formatting.
- **Vitest** in every package. The Worker's tests run inside workerd through `@cloudflare/vitest-plugin`. **Playwright** (Chromium) runs the web end-to-end suite against the Vite dev server.
- **Worker types** come from `wrangler types` (runtime types for the configured compatibility date plus `Env`), regenerated by `task types` and not committed, instead of `@cloudflare/workers-types`, as Cloudflare recommends.
- **Taskfile** is the command interface (`setup`, `dev`, `check`, `test`, `e2e`); **GitHub Actions** runs `task check` and the Playwright suite on pull requests and pushes to `main`.
- The Worker uses only Free-plan features so far: a SQLite-backed `NoteDoc` Durable Object. Queues, D1, R2, Vectorize and Workers AI bindings arrive with the tasks that use them.

## Consequences

- One `task check` gates every package locally and in CI.
- The workspace stays on TypeScript 6 until typescript-eslint supports TypeScript 7.
- Free versus Paid: the T1 check could not tell which Workers plan the account is on (the worker API token excludes billing, and the account's `default_usage_model` reads `standard` on both plans). The configuration only uses Free-plan features. T4 and T6 should confirm the plan in the dashboard (Workers & Pages → Plans) before adding anything that needs Paid.
