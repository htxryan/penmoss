# Penmoss for Mac: for contributors

**Installing and using the Mac app is in the user docs: [Install on Mac](https://penmoss.app/docs/install/mac/) and [The Mac app](https://penmoss.app/docs/mac/).** This page keeps how it is built, tested and released, and the manual checks.

The Mac app is an Electron shell around the Penmoss web app, bundled inside it. Its notes live in git notebooks: git repositories you choose, which this Mac's own git syncs (D43, T50). Since D49 (T59) there is no Penmoss server, so the app has no sign-in, account or devices: it starts into your git notebooks, and opens and edits them offline.

- **Code:** `apps/desktop/` (main process and preload) and `apps/web/src/desktop/` (the web app's side). Quick capture: `apps/web/src/capture/` and `packages/editor/src/capture.ts`.
- **Design:** decisions A220–A229, A850–A869 and A1051 in [`decisions.md`](decisions.md). Builds on the Releases page: A403.
- **Tasks:** T29 (the app), T30 (quick capture), T50 (git notebooks) and T59 (no server) (issues #29, #30, #147 and #191).

## 1. How it fits together

| Part                                       | What it does                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `app://penmoss/`                           | A privileged custom scheme (secure, standard, fetch, code cache) served by `protocol.handle` from `dist/web` inside `app.asar`. Unknown paths fall back to `index.html`; every response carries the app's own CSP (`src/csp.ts`), whose `connect-src` is `'self' blob:`: the page connects nowhere else (A1051).                                                      |
| Main process (`src/main.ts`)               | Windows and their saved size and place, native menus, git notebooks (it runs git and checks each call, A853), the owner check (Touch ID), local agents and `--penmoss-cli`, the clipboard, deep links, the capture hotkey, Send feedback with your GitHub token, Auto-Update (A1112).                                                                                 |
| Preload (`src/preload.ts`)                 | Exposes `window.penmossDesktop` (typed in `apps/web/src/desktop/bridge.ts`) through `contextBridge`. Each call is one IPC message; the page never gets Node or Electron. The main process answers only the main frame of an `app://penmoss` page.                                                                                                                     |
| Embedding service (`src/embed-utility.ts`) | Search by meaning (T76, A1152): a `utilityProcess` main forks 2 s after launch and restarts after a crash. It downloads EmbeddingGemma to `~/.penmoss/models` unless Settings → Search by Meaning is off, holds the indexing lease, indexes the notes the page sends and answers its queries. The page reaches it only through main's `penmossDesktop.meaning` calls. |
| Web app                                    | Detects the bridge. Runs each git notebook's engine and hands git to the main process, describes its menus from the command registry, writes copies through the native clipboard, and skips the service worker (the bundle is already local).                                                                                                                         |

## 2. Develop and test

```sh
task desktop:build     # web bundle (PENMOSS_BUILD=desktop) into apps/desktop/dist/web, then main + preload
task desktop:test      # unit tests, then Playwright for Electron (xvfb-run on Linux)
task desktop:package   # .dmg and .zip in apps/desktop/release (section 3)
```

The Playwright tests start only a fake GitHub, on a port of this checkout's own (A1177; `PENMOSS_DESKTOP_FAKE_GITHUB_PORT` picks another) (`test/e2e/fake-github.ts`, for Send feedback and the GitHub token check). Each test adds a git notebook on a bare repository on this machine (`file://`) through Settings → Git Notebooks, with a stand-in for the owner check, and reads what was pushed from that repository. They edit a note, quit, relaunch with the network blocked and find the note, then check menus and shortcuts, `penmoss://` links, the clipboard, outside links, window state, git notebooks over `file://` and HTTP beside the CLI, note windows, local agents, full width, the Info panel, the status bar and the sidebar rail, Send feedback and the capture window. Electron downloads its binary on first use into `~/.cache/electron`.

In an unpackaged build, `PENMOSS_USER_DATA` and `PENMOSS_WEB_ROOT` override the defaults, and the `PENMOSS_TEST_*` variables (the owner check's stand-in, git's configuration, the home folder, the GitHub API, and for Sign in with GitHub `PENMOSS_TEST_GITHUB_WEB` and `PENMOSS_TEST_GITHUB_CLIENT_ID`, with which main logs the sign-in page instead of opening a browser) serve the tests. A packaged app ignores them all.

## 3. Release

### Install from the Releases page (every merge to main, A403, A1188)

Every merge to main is an **Alpha build** (P3–P5). It gets a prerelease, `build-<run>`, on [Releases](https://github.com/htxryan/penmoss/releases): the Android APK as soon as its tests pass, and the Mac app, `penmoss-mac-<build>.dmg`, once CI has built it. A `build-<run>` release is never Latest: Latest is only ever a stable `vX.Y.Z` release (none yet, so `/releases/latest` answers 404 until v0.2.0). The newest Alpha build is also on the rolling [`alpha`](https://github.com/htxryan/penmoss/releases/tag/alpha) prerelease under fixed names: `Penmoss.dmg`, `Penmoss.apk`, the update zip `penmoss-mac-<build>.zip`, `alpha-mac.yml` (the Alpha channel's update feed, uploaded last) and `SHA256SUMS.txt`, with its tag on that build's commit; the previous zip stays until the next build, so an update already downloading can finish. Its version is `X.Y.(Z+1)-alpha.<build>` counted from the newest stable tag (`0.2.0-alpha.<build>` before the first), which About Penmoss shows with the build number. The Mac app is universal (P7, A1186): one dmg runs on Apple Silicon and on Intel Macs (macOS 12 or later). GitHub's standard hosted Mac runner (`macos-latest`, Apple Silicon, free for this public repository; A1348, [`ci.md`](ci.md)) builds it on a fresh machine for each job, and a newer merge cancels an older build still running, so only the newest is built. A release without its own Mac app carries the newest earlier one, and its notes say which build that is, so every build release has a Mac app.

1. Download `Penmoss.dmg` from the `alpha` release (or a build's dmg), open it and drag **Penmoss** to **Applications** (replace the older copy if asked).
2. First launch: the app is signed ad hoc, not with a Developer ID, and not notarised, so macOS blocks it once. Open Penmoss, close the warning, then choose **Open Anyway** in System Settings → Privacy & Security. Or, in Terminal: `xattr -dr com.apple.quarantine /Applications/Penmoss.app`.
3. A new build may ask once to use the keychain item “Penmoss Safe Storage” (where the key for git notebook tokens and your GitHub token lives): choose **Always Allow**. Each ad hoc build looks like a new app to the keychain.

About Penmoss shows the version and the build number (`CFBundleVersion`). A signed build updates itself (Settings → Updates). The last 10 builds are kept.

**How CI builds it** (`.github/workflows/ci.yml`): the `mac` job runs on pushes to main and on `workflow_dispatch`, not on pull requests, on GitHub's hosted Mac (A1348). It runs `task desktop:package` with `PENMOSS_MAC_ARCH=universal` from a clean checkout, then `.github/scripts/mac-check.sh`: it checks the signature (`codesign --verify --deep --strict`, ad hoc unless a certificate secret is set), logs Gatekeeper's verdict (`spctl -a -vv`, a rejection until the app is notarised), checks with `lipo -archs` that every Mach-O file in the app (the main executable, the helper apps, each framework and library, and the owner check) has both `arm64` and `x86_64` (`.github/scripts/mac-archs.sh`), and mounts the dmg to verify the copy inside. A newer build of the same branch cancels one still waiting or running. The `mac-release` job then attaches the dmg to its commit's release and to newer releases still holding an older one (`.github/scripts/releases.mjs`, tested by `task releases:test`), but only once the `mac` job's checks and the build's APK release (`android-release`) have passed in the same run. The Mac app's Electron suite runs in the same run's `desktop` job, on a hosted Ubuntu runner under xvfb (A1235); it doesn't hold the release back.

To build a branch's Mac app without publishing, run `gh workflow run ci.yml --ref <branch>`; the dmg is the run's `penmoss-mac` artifact. A dispatch never publishes, even on main: its run number is not the build's, so the dmg's name and the app's `CFBundleVersion` would disagree.

**When the Mac app is missing from a build:**

- **`mac-release` was cancelled.** The release jobs share one concurrency group, which holds one job running and one waiting; a third arriving cancels the waiting one. A release job can run for minutes (`publish-apk` carries the newest Mac app, a 121 MB dmg, into the new release), so merges a few minutes apart can hit this. Re-run just that job in its push run (the job's page → **Re-run this job**, or `gh run rerun --job <job-id>`) within 7 days, while the run's `penmoss-mac` artifact exists. Older than that, re-run the run's failed jobs, which builds the dmg again. A cancelled `android-release` is re-run the same way, while its APK artifact exists (7 days).

**Signing (A406, A1348).** The `mac` job names the GitHub environment `mac-signing` (limited to `main` by a deployment branch policy) on pushes to main only, so a dispatch on any branch gets no signing secret. The job runs on a hosted runner that GitHub throws away afterwards, so nothing an earlier job did can reach the secrets (the risk A406 accepted for the self-hosted Macs is gone; [`ci.md`](ci.md) §7). Add the secrets to `mac-signing` only, never as repository secrets. The `mac` job reads `PENMOSS_MAC_CSC_LINK` (the Developer ID Application `.p12`, base64), `PENMOSS_MAC_CSC_KEY_PASSWORD`, and for notarisation `PENMOSS_MAC_APPLE_API_KEY` (the App Store Connect `.p8` key's text), `PENMOSS_MAC_APPLE_API_KEY_ID` and `PENMOSS_MAC_APPLE_API_ISSUER`; electron-builder then signs and notarises as below. CI never signs with an identity from a keychain of Ryan's.

### Stable releases (a version tag, P3, A1189)

A stable release is a `vX.Y.Z` tag. Ryan runs `task release -- X.Y.Z` on a clean, up-to-date `main` (`-- X.Y.Z --dry-run` only checks); it pushes the annotated tag, and `.github/workflows/release.yml` builds a signed, notarised universal dmg and the release APK on the Mac runners and creates a **draft** release with `Penmoss.dmg`, `Penmoss.apk`, `penmoss-mac-X.Y.Z.zip`, `SHA256SUMS.txt` and `latest-mac.yml`, and notes since the previous stable tag. The job fails rather than publish an app `spctl` does not call notarised. Ryan edits the notes and publishes the draft, which makes it Latest: `https://github.com/htxryan/penmoss/releases/latest/download/Penmoss.dmg` then serves it, and the Stable channel reads `…/releases/latest/download/latest-mac.yml`. `X.Y.Z-rc.N` makes a draft prerelease, for a rehearsal. The steps, the checks and the environment change Ryan makes first are in [`ci.md`](ci.md) §10.

### Release by hand

Do this on the Mac. Electron-builder can make a Mac zip on Linux, but it cannot sign or notarise one there, and the agent worker never holds the certificates.

#### Credentials (environment only)

Nothing is stored in the repository. Set them in the shell for the one command, or in a password manager's CLI wrapper:

| Variable                                                   | Purpose                                                                                                                                       |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `CSC_LINK` + `CSC_KEY_PASSWORD`                            | A Developer ID Application certificate exported as `.p12` (path or base64). Or `CSC_NAME`: the name of one already in the login keychain.     |
| `APPLE_API_KEY`, `APPLE_API_KEY_ID`, `APPLE_API_ISSUER`    | Notarise with an App Store Connect API key (preferred).                                                                                       |
| `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID` | Or notarise with an Apple ID and an app-specific password.                                                                                    |
| `PENMOSS_BUILD_NUMBER`                                     | The CI build (the run plus 1000, D65): the build in About Penmoss and the `penmoss-mac-<build>` file names (A1015).                           |
| `PENMOSS_APP_VERSION`                                      | The version (P5, A1188): `X.Y.(Z+1)-alpha.<build>` on main (`releases.mjs version`), `X.Y.Z` for a stable release; without it, `0.1.<build>`. |
| `PENMOSS_MAC_ARCH`                                         | `arm64` (default) or `universal` (Apple Silicon and Intel). CI always builds `universal` (P7, A1186).                                         |

Without a signing identity the build is **signed ad hoc** (A403): Apple Silicon runs no code without a valid signature, so a truly unsigned app is reported as damaged. A hook in the config forces the ad hoc identity (`-`), so no identity from the login keychain is ever used. It is not notarised, has no update feed, and auto-update stays off (the app logs `auto-update: unsigned`). A signed build updates from GitHub Releases, Stable or Alpha (A1196). Open it the first time with Open Anyway in System Settings → Privacy & Security.

#### Steps

1. `pnpm install` and `task check`.
2. CI builds every merge to main this way on GitHub's hosted Mac (A403, A1348): `PENMOSS_BUILD_NUMBER` is the build and `PENMOSS_APP_VERSION` its alpha version, so electron-updater sees each build as newer (P5).
3. With the variables set: `task desktop:package`. Signing, hardened runtime and notarisation run inside electron-builder; the output is `apps/desktop/release/penmoss-mac-<run>.dmg`, the `.zip`, its `.blockmap` and the feed (signed builds only): `alpha-mac.yml` for an alpha `PENMOSS_APP_VERSION`, else `latest-mac.yml`. The app's `Resources/app-update.yml` names the `generic` provider on GitHub Releases (`…/releases/download/alpha`, or `…/releases/latest/download`; P6). A stable build is named for its version, `penmoss-mac-X.Y.Z` (P2).
4. Check it: `spctl -a -vv apps/desktop/release/mac-universal/Penmoss.app` (`mac-arm64` without `PENMOSS_MAC_ARCH=universal`) should say `accepted, source=Notarized Developer ID`, and `codesign --verify --deep --strict` should be silent.
5. CI's `mac-release` job attaches the dmg, the zip and the feed (last, as `latest-mac.yml`) to the build's release and carries them to newer releases (`.github/scripts/releases.mjs`, A1015), then replaces the Mac files on `alpha` (A1188). By hand: `node .github/scripts/releases.mjs publish-mac --sha <sha> --dmg <dmg> --zip penmoss-mac-<run>.zip --feed alpha-mac.yml`, then `node .github/scripts/releases.mjs publish-alpha --run <run> --sha <sha> --version <version> --dmg <dmg> --zip penmoss-mac-<run>.zip --feed alpha-mac.yml`; `--dry-run` prints what either would change.
6. downloads.penmoss.app, the R2 bucket earlier installs updated from (A1112), is retired (A1206): CI no longer publishes there, and every install reads GitHub Releases (A1196). Its Worker, custom domain and bucket are deleted on Ryan's word only; until then they serve the last build put there, which is one that reads GitHub.
7. Installed apps update from GitHub Releases with no token (A1196). Settings → Updates → **Update Channel** picks where from: **Stable** (the default) reads `latest-mac.yml` on the latest release, https://github.com/htxryan/penmoss/releases/latest/download/, and **Alpha** ("Every build from main. Newest features, may break.") reads `alpha-mac.yml` on the rolling `alpha` prerelease, https://github.com/htxryan/penmoss/releases/download/alpha/. The choice is kept in `updates.json` in the app's userData, next to Auto-Update. Switching checks at once, whether Auto-Update is on or off, and still only offers the build. Updates never go to an older version: an Alpha build switched to Stable stays on its build until a stable release is newer, and the status line says it moves to Stable with the next stable release. **Auto-Update** (off until turned on) checks 10 s after launch and every hour; **Check Now** and Penmoss → Check for Updates… check any time. A newer build is offered in Settings and in a notice; **Install and Restart** downloads it and restarts into it.

## 4. Behaviour worth knowing

**How the Mac app behaves for someone using it is in the user docs: [The Mac app](https://penmoss.app/docs/mac/)**, with [Quick capture](https://penmoss.app/docs/quick-capture/), [Updates](https://penmoss.app/docs/help/updates/), [Themes and fonts](https://penmoss.app/docs/themes/) and [Search](https://penmoss.app/docs/search/). What follows is how it is built.

- **Starting:** the app opens on your git notebooks (section 6), or the first run (`apps/web/src/sources/FirstRun.tsx`) with none. The page never talks to `api.penmoss.app` or `app.penmoss.app`, which are gone (D49).
- **The owner check (T41, A504, A855):** removing a git notebook, connecting an agent or disconnecting one with unpushed changes, Restore and Revert in a git note's History, and Delete for good each first ask macOS to check it is you: Touch ID, or the Mac's password when Touch ID is locked out, the lid is closed or no finger is enrolled. It is never a plain Cancel/Allow confirmation. The check is a small signed helper in the app (`Contents/Resources/auth/Penmoss`, built from `native/penmoss-auth.swift` when the app is packaged). If it is missing or will not run, every such change is refused with “Reinstall Penmoss”. The main process asks it, in words from the main process, never the page's (`AdminCheck.confirmOwn`, A1051).
- **Secrets** (git notebook tokens, your GitHub token) are encrypted with `safeStorage` (the Keychain on a Mac) in the app's data folder and never reach `localStorage` or IndexedDB. On Linux without a keyring, Electron falls back to its fixed-key `basic_text` backend, which the app treats as no encryption; only the Playwright suite opts in, with `PENMOSS_TEST_BASIC_TEXT_STORAGE=1` in an unpackaged build.
- **Menus** come from the command registry (`apps/web/src/desktop/menu.ts`), with each command's current shortcut, beside the system's own items. When a menu takes a shortcut the page already handled, the second run is dropped.
- **Copy commands** write HTML, plain text and markdown (`net.daringfireball.markdown`) as one clipboard item, and only after a key press, click or menu command.
- **Links:** `penmoss://note/<id>` and `penmoss://capture` (`src/deep-link.ts`); `http`, `https` and `mailto` open in the default browser, and the app's windows never navigate away from `app://penmoss`.
- **Quick capture (T30, A90, A915):** the hotkey (default ⌃⌥⌘N, `src/hotkey.ts`) is checked by the main process: two modifiers including ⌘ or ⌃, and not a key that copies, pastes, undoes or edits text; it changes only right after a gesture in Settings, at most 5 times a minute. On a Mac the capture window is a panel, so it shows over a full-screen app while Penmoss stays a regular app. Each launch, Console shows `NSWindow does not support nonactivating panel styleMask 0x80` twice. It comes from Electron's panel and is harmless (A915).
- **Note windows (T45, D37, A710–A714):** 720×800, each a step from the window in front (`src/windows.ts`). The main window runs each notebook's engine; note windows and quick capture hand their edits to it, and if the main window closes, a note window takes over. Note windows are not reopened after a relaunch.
- **Keep on top (T46, D38, A720, A721)** and **the compact title bar (T47, D39, A722–A724):** `src/mac-window.ts`. The double-click on the top row is Chromium's (A723); if it fails on a Mac, the follow-up is a native handler in the main process, not a page listener.
- **The menu bar icon (T51, A945):** `src/tray.ts`, on by default (T53 item 6), this Mac's own preference.
- **Send feedback (T49, D41, A798, A1010):** the app captures the window in front first (`capturePage`, no screen-sharing prompt) and offers it unticked; the main process files the issue with your GitHub token. The rest is the web's form ([feedback.md](feedback.md)).
- **Theme (T28, A249):** the windows' background and the title bar follow the theme, and the next launch opens in it.
- **Search by meaning (T76, D59, A1151–A1158):** the embedding service (section 1) downloads the model once into `~/.penmoss/models`, where `penmoss models` and `penmoss mcp` find it too. The vectors are in `~/.penmoss/vectors`, shared with the CLI; the app indexes and collects them, and an agent's `penmoss mcp` indexes only while the app does not. Off, kept in `~/.penmoss/meaning.json`, removes the model and the vectors.
- **Quitting** asks the page to store any unsaved keystrokes first (waits up to 3 s), then push its git notebooks (section 6).

## 5. Manual check on the Mac

1. Install from the `.dmg` and launch it: it opens with no sign-in. Add a git notebook (section 6's check, step 1). The dmg is universal (P7): also launch it as Intel code, on an Intel Mac or under Rosetta with `arch -x86_64 /Applications/Penmoss.app/Contents/MacOS/Penmoss` (Activity Monitor's Kind column says Intel), and open a notebook there too.
2. Open and edit notes; turn Wi-Fi off, quit, relaunch, and check the note opens and edits; turn Wi-Fi on and see the edit reach the repository.
3. Walk the menus: every command has its shortcut, ⌘, opens Settings, the shortcuts work with the menu bar.
4. Copy a note as rich text and paste into Apple Notes and Mail; copy as markdown into a text editor.
5. From Safari and Terminal press ⌃⌥⌘N, type, ⌘Enter; check today's note on the phone after both have synced. Type, click another app, press ⌃⌥⌘N again: the text is still there.
6. The owner check, on **Remove** for a git notebook you added only for this: Touch ID asks with “Penmoss is trying to remove the git notebook at … from this Mac”. Cancel it: nothing is removed, and the page says “Not done: this Mac did not confirm it was you.” Then allow it.
7. The owner check's fallbacks:
   - **Password:** at the Touch ID prompt, choose **Use Password…** and type the Mac's password; the change goes through.
   - **Lockout:** use the wrong finger until Touch ID locks out (about five tries). The next owner check asks for the password instead; Cancel refuses it.
   - **Lid closed:** with the lid closed on an external display, the check asks for the password.
   - **Never a dialog:** none of these shows a plain Allow button.
8. Press ⌘⌥⇧W, ⌘⌥⇧I and ⌘\\ in a note: full width, the Info panel and the sidebar rail; type and watch the status bar's counts and Saved · in git.
9. In the sidebar, ⌘-click two notes, then Ctrl-click one of them: Penmoss's menu opens (no macOS menu), offering Move 2 notes… and Move 2 notes to Trash; with a trackpad, a two-finger click does the same. Move them into a folder, then Trash them and Undo. Ctrl-click a folder: Rename and Delete folder….
10. Click a `penmoss://note/<id>` link in another app, and run `penmoss open <id>` in Terminal.
11. Turn on Settings → Updates → Auto-Update, merge to main (or wait for the next build), and confirm the notice offers it within the hour (or at once with Check Now); Install and Restart restarts into it, and About Penmoss shows the new build. The log says `update <version> is available` (`0.2.0-alpha.<build>` from A1188), then `downloaded`. Then switch Update Channel to Alpha: it checks at once and offers the newest build from main; back on Stable, a stable release reports up to date, and an Alpha build says it moves to Stable with the next stable release (A1196).
12. **Note windows (T45).** In a note press ⌘⌥O, then choose Open in new window from the ⋯ menu: two windows on the note, each a step from the window in front. Type in one and watch the other and the main window. Click a link in a note window, then ⌘[ and ⌘]. ⌥-click a sidebar note. With a note window in front, “Collapse or expand the sidebar” is greyed out in the menus and “Show or hide the Info panel” acts on that window. Turn Wi-Fi off and type in each window: the others follow. Close the main window, click the Dock icon: it comes back with the note windows still open. Quit and relaunch: only the main window opens.
13. **Keep on top and the compact title bar (T46, T47).** Screenshots go in `docs/evidence/t46/` and `docs/evidence/t47/`, light and dark.
    - **Keep on top:** open a note window, click its pin (or View → Keep on top) and click Safari: the note window stays above Safari. Switch Space (⌃→): it comes along. Make Safari full screen: the note window does not float over it. Click the pin again: it goes back behind Safari. With each window in front, View → Keep on top's tick matches that window's pin. Pin the main window, quit and relaunch: it opens pinned; the note windows are gone.
    - **Compact title bar, every layout:** the lights sit centred in the first row, with nothing under or beside them, with the sidebar open, as a rail (⌘\\), at full width (⌘⌥⇧W), in Settings, the graph, a window narrower than 700 px (and its drawer), and a note window. Screenshot each, light and dark, with the setting on and off (before and after). Measure the note's title: about 28 px higher than with the setting off, in the main window and a note window.
    - **Drag and double-click:** drag the sidebar header, a note's top bar and a note window's top bar: the window moves; every button in them still clicks. In System Settings → Desktop & Dock set "Double-click a window's title bar to" Zoom, then double-click an empty part of the top row: the window zooms, and again it goes back. Set Minimize: it goes to the Dock. Double-clicking a button never zooms. Chromium handles this itself (A723); if it fails on a Mac, the follow-up is a native handler in the main process, not a page listener. In a window narrower than 700 px open the drawer and click its Close button and its items where they lie over the app bar: each clicks, none drags. Right-click a folder or note in the sidebar near the top so its menu reaches over the note's top bar: every item clicks, none drags; with the menu closed the top bar drags again.
    - **Full screen:** ⌃⌘F: the lights hide and the sidebar header has no gap before the brand; leave full screen and the gap is back, with the lights centred in the first row again (not where macOS's own title bar puts them). Pin a note window and press ⌃⌘F on it: it goes full screen on its own Space, and leaving full screen it is still pinned. Pin the main window, make it full screen and quit: it relaunches full screen, and leaving full screen it is still pinned.
    - **The setting:** Settings → Appearance → Compact title bar off: Penmoss asks; Cancel leaves it on. Again, Reopen windows: the windows come back with macOS's title bar, where they were, a pinned note window still pinned, a maximized or full-screen window still so, Settings still open, and the window that was in front still in front. Type in a note and flip the setting straight away: what you typed is there after the reopen. Turn it on again the same way. Quick capture (⌃⌥⌘N) looks as before either way.
14. **Send feedback (T49, T57; a GitHub token saved).** In a note window choose Help → Send feedback: the form opens there, This window.png shows that window and is unticked. Tick it, choose Bug report and P4, title it `[test] Mac feedback`, paste a screenshot (⌘⇧⌃4) and Send: a toast links the new issue, which shows both images and the context naming the Mac app and the note window. Close the issue as not planned.
15. **A capture at launch, and how the launch started (T39 pass 3, A904).** Quit Penmoss, open it from the Dock and press ⌃⌥⌘N straight away. The capture window keeps the focus while the main window shows. Press Escape: the main window stays in front. Then in System Settings → General → Login Items, add Penmoss under Open at Login, log out and log in, and press ⌃⌥⌘N once the menu bar shows Penmoss. Press Escape: Penmoss hides again. Open `~/Library/Application Support/Penmoss/launch.log`. Its last two lines say `wasOpenedAtLogin=false` for the Dock launch and `wasOpenedAtLogin=true` for the login. If the login line says `false`, `wasOpenedAtLogin` is not reliable on this macOS: say so on the PR, so the app can stop relying on it (A904). Take Penmoss out of Open at Login afterwards if you don't want it there.

## 6. Git notebooks

**Adding, syncing and removing notebooks is in the user docs: [Your first notebook](https://penmoss.app/docs/first-notebook/), [More devices](https://penmoss.app/docs/more-devices/), [Sync, offline and merging](https://penmoss.app/docs/help/sync/) and [Settings](https://penmoss.app/docs/reference/settings/#git-notebooks).** A git notebook keeps its notes in a git repository you choose (D43, T50), and since T59 it is the only kind. The CLI and `penmoss mcp` work on the same repository ([cli.md](cli.md)). Evidence: [`docs/evidence/t50/g3-g6.md`](evidence/t50/g3-g6.md).

- **git runs in the main process** (`src/git-notebooks.ts`), which checks each call (A853); the page hands it git through `penmossDesktop`. Settings' actions are commands too (`apps/web/src/sources/git-commands.ts`, #170 F5), in the File menu and the palette.
- **Identity.** git's `user.name` and `user.email` are read again for each commit, with a `Penmoss-Writer` trailer; a notebook's own Commit name and Commit email (#170 F6) go over them. Commits are signed when git's configuration signs them.
- **Your Repositories (T81, D60).** The main process asks this Mac's git for its github.com sign-in (`git credential fill`, never prompting) on each call, sends it only to api.github.com, and lists up to 300 repositories. The page never sees the credential.
- **Sign in with GitHub (T82, D63).** The device flow (`src/github-device-sign-in.ts`) with Penmoss's OAuth app, "Penmoss" on htxryan's GitHub account (A1173), whose public client id is `GITHUB_CLIENT_ID` in `src/config.ts`. The token is kept in the store Settings → Status → GitHub Token uses, and becomes the token of a notebook added with it from github.com over HTTPS. git's own sign-in is tried first. A test run with a stand-in GitHub API uses only its own stand-in's sign-in.
- **No privacy check (D61) and git's own configuration (D62).** Penmoss does not ask anyone whether a repository is private. git follows its own configuration, `insteadOf` and `pushInsteadOf` rewrites included. A remote with a user name or password in it is refused.
- **Delete for good (A855, A894).** It is checked in the main process, for that note, for 10 minutes: a sync that would delete any other note's files, or empty or cut any log in the repository, is refused. One that waited longer (offline) is confirmed again through **Confirm Delete for good again…**. A note never confirmed on this Mac is listed apart, and the sync stays stopped until you choose **Keep note** or **Delete for good** for each. A Delete for good that has reached the repository is never taken back. Every prompt names the repository and then the note by its title as the repository has it, never by what the page says.
- **Sync timing (A1013, #170 F8, F9).** Push 12 s after edits settle (within a minute while typing goes on), pull every minute while shown and on focus, per notebook. Quitting or closing a window pushes for up to 10 s; a push that cannot finish is stopped and pushed first at the next launch. Offline is detected from the Mac's network; an unreachable host is retried from 30 s, doubling to 10 minutes.
- **History (A901).** Restore and Revert ask Touch ID, naming the note as the branch has it, then push the note as it is as a version of its own and make a new change. Offline, they refuse.
- **Agents (T54, A993).** Settings → Agents, not Git Notebooks, connects agents since A1098 (`apps/web/src/sources/AgentsSettings.tsx`, `LocalAgents.tsx`; [cli.md](cli.md)).
- **No git outlives Penmoss:** quitting, or a signal to the app, stops its git processes, and any a crash left are stopped at the next launch (`git-processes.json`).

### Manual check on the Mac (T50 G3–G6)

Use a private repository only. `htxryan/penmoss-git-notebook-scratch` and `htxryan/penmoss-git-notebook-code-scratch` are there for this; use a new branch each time.

1. Install the build from Releases and launch it. View → Git notebooks. Add `https://github.com/htxryan/penmoss-git-notebook-scratch.git`, branch `mac-<today>`, name `Mac check`. Nothing asks to confirm anything, and no line says whether the repository is private (D61).
2. Paste a GitHub token that can read the repository into **Use a personal access token** and save: the next sync uses it, and the token is never shown again.
3. Add a second notebook (`htxryan/penmoss-git-notebook-code-scratch`, below): the sidebar shows both side by side. Click Mac check's **Top level**, press ⌘⌥N, type a title and a line. **Sync now**: the note's `.md` appears on the branch on github.com, with your git name on the commit.
4. In Terminal: `gh auth token | penmoss notebook add https://github.com/htxryan/penmoss-git-notebook-scratch.git --branch mac-<today> --name check --token -` (or `PENMOSS_GIT_TOKEN=… penmoss notebook add …`, or git's own credentials with no token), then `penmoss new "From the CLI" --notebook check`. In the app, **Sync now**: the note appears in Mac check's section, not in the other.
5. Open the git note in a window of its own (⌘⌥O), type in it, close it, and quit Penmoss at once: the section says **Pushing…** until the push lands (up to 10 s). `penmoss cat <id> --notebook check` shows the typing. If the push could not finish in time, the next launch pushes it first, and `penmoss cat` shows it once that has synced.
6. Version history (⌘⌥⇧H) on that note lists its commits with authors; restore the first version, sync, and check the CLI sees it.
7. Settings → Daily notes → Journal notebook → Mac check; Today (⌘D) makes the daily note in Mac check.
8. Search for a word from the git note: the hit is labelled Mac check.
9. Turn Wi-Fi off: the section says Offline at once (not Synced · 1 waiting, nor Syncing for ever); edit; **Sync now** still tries and says it could not reach GitHub (#174 review); turn Wi-Fi on: the edit is pushed within seconds, without Sync now. Opening Quick capture (its hotkey) and editing a note's title never show Pushing….
10. The code repository's notebook (`https://github.com/htxryan/penmoss-git-notebook-code-scratch.git` with directory `docs/notes`): its files land under `docs/notes/` only.
11. Remove both notebooks (Touch ID asks for each). They leave the sidebar; the branches on GitHub keep everything.
12. Screenshots of the side-by-side sidebar and Settings → Git notebooks, light and dark, go in `docs/evidence/t50/g3-g6/`.
13. **Commands and menus (#170 F5).** With a Mac check note open, the File menu and the palette (type `git`) list Sync this git notebook now, Sign this git notebook's commits, or stop, Set when this git notebook pushes…, Set how often this git notebook pulls…, Use a token…, Forget this git notebook's token, Set this git notebook's commit name and email…, Confirm Delete for good again… and Remove this git notebook from this Mac….
