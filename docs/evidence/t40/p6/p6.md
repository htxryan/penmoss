# T40 P6 · Search, actions and tags on Android

Evidence for T40's P6 ([issue #76](https://github.com/htxryan/penmoss/issues/76)), one PR:

- One search (FD2): Hybrid always, as T42 makes the web's; offline, or when meaning cannot answer, a quiet Words only in T42's words;
- Filters (FD3): Folder (with subfolders), Tag (with nested tags) and Updated, sent to the route online and applied in Room offline;
- Marked results (FD1): titles and snippets paint the matched words in the theme's search colour; semantic hits show ≈ and their heading;
- The offline full-text index (FD4): Room FTS4 over each note's plain text and headings, folded as the server's unicode61 folds it and ranked as the web's offline index, from `text` in `/sync/batch` and from the editor page's new `text` message;
- Recent notes (FD7): Home's Recent ranks by opened here or edited anywhere; Ctrl+E opens the recent-notes switcher;
- Actions in Search (FD6): an **Actions** section above the notes from `contract/commands-v1.json`, which lists every web command with how a phone reaches it; Ctrl+K opens Search with every action;
- Tags (TG1, TG2): **Tags** in Home's menu, the tree with counts as the web's tag pane, and a tag's notes, offline, with this phone's own tag changes at once;
- Rename and merge (TG3): through `POST /api/tags/rename`, once this phone's edits are sent, shown here at once;
- Inline tags (TG5): a `#tag` tapped while reading, or Ctrl-tapped, opens its notes (`openTag`);
- Server: `text`/`headings`/`textHash` in `/sync/batch` and `tags` in `/sync/changes` (the offline Tag filter and the tag browser need them), whose query now limits each half before the union. Rename reuses the existing route.

Decisions A460–A469 are in [`decisions.md`](../../../decisions.md). Room schema 15 (after P8's 13 and P7's 14).

**Not walked through on a device:**

- **Ctrl+E with the editor's WebView focused**: the activity's `dispatchKeyEvent` sees every key before any view, so the path is the same as the tests'; the Pixel checklist presses it in a note with a hardware keyboard.
- **Ranking against the server's**: held to the web's `LocalSearchIndex` (which A101 holds to the server's) by `search-ranking-v1.json`, over text folded as unicode61 folds it (`search-fold-v1.json`); the checklist compares the same query on both.
- **A rename end to end**: the route is the web's (T24), tested in workerd already; the phone's request and its reply are tested against a canned server. The checklist renames on the Pixel and checks the web.
- **The keyboard staying down on a reading tap**: the page prevents the tap's focus, which the test checks; whether Android's WebView raises the keyboard anyway is for the checklist.
- **The first fill's bandwidth on a real vault**: text comes with exchanges, at most one pass's batch limit (2,000 notes) a pass, only on Wi-Fi or in front.
