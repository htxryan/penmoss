# T40 P4 · Folders on Android

Evidence for the fourth slice of T40's P4 ([issue #76](https://github.com/htxryan/penmoss/issues/76)):

- New folder, rename, delete, move a folder and sort modes per folder + top level (NT2–NT6): a Sort menu (Manual, A–Z, Last modified) queuing `PATCH /api/folders/:id` (or `PATCH /api/folders/root` for the top level);
- Manual reorder of folders and notes (NT7, adapted): a Reorder mode (drag handles, TalkBack actions, Alt+↑/↓, Done);
- Rename from lists (NT10): the long-press sheet gains Rename, opening the note with the caret in its title;
- The breadcrumb (NT11): the note's top bar shows the folder path, tappable, with every level on long press;
- Server: `POST /api/folders`, `PATCH /api/folders/:id`, `PATCH /api/folders/root`, `DELETE /api/folders/:id`, and `place` on `POST /api/notes/:id/move`.

Decisions A440–A449 are in [`decisions.md`](../../../decisions.md).

## How it was run

- **No emulator session: blocked on KVM.** As in P3b, the worker's `penmoss36` AVD exists but this session's user has no KVM permission, so the emulator never boots. The Pixel checklist below (in [`docs/android.md`](../../../android.md#test-folders-on-the-pixel-t40-p4)) is for Ryan, and the flows it checks are covered by the tests below.
- **What covers it instead:**
  - Server route tests in workerd (`folders.test.ts`, 22): create idempotent by id, missing parent, blank name, agent and read-only refused; rename/move with preconditions and 409s, retry-after-applied answers 200 (T40 P4 review B1), cycle refused, missing folder 404, sort set and refused; root sort; delete moves notes up, idempotent delete; folder and note reorder with anchors, stale anchor at the end.
  - Scope tests (`folder-scope.test.ts`, +4 probes): each new route probed with a scoped token (refused, hidden); the move probe carries `place` (T40 P4 review nit).
  - Robolectric store tests (`FolderStoreTest`, 15): every action shows at once and queues its op; cycle/unknown refused; create+delete cancels out, a tried create queues the delete instead (T40 P4 review B3); sorts coalesce; reorders with anchors; an old tree keeps waiting changes; web-deleted folders drop ops with a deleted notice, overtaken ones say renamed/moved (T40 P4 review B2); silent delete-op drop.
  - Robolectric sync tests (`FolderSyncTest`, 12): offline create/rename/move/sort reach the server in order; a note filed into an offline-made folder arrives after it; overtaken rename dropped with a renamed notice; applied-retry keeps later changes (rename and move); tried create+delete leaves no reappeared folder; web delete drops with notice; reorder sends `place` and takes the server's order; root sort sent; create under a deleted parent falls back to the top level; folder changes count as unsent; older servers wait (A449).
  - Robolectric UI tests (`FolderScreensTest`, 14): sheet actions, name dialog validation, delete counts, sort menu, breadcrumb tap and levels, reorder handles and custom actions with anchors, Home and FolderScreen wiring, Back (bar and system) ending Reorder mode (T40 P4 review S6).
  - Unit tests: `OrderKeysTest` (3, golden vectors from the TypeScript implementation), `FolderTreeTest` (+3 `reorderKey`, including invalid-key tolerance), `HttpPenmossApiTest` (+1 folder routes and `place`), `ItemsTest` (+2 path and exclusion), `MigrationTest` (+2 schema 9→10, schema 10→11 untried ops).
  - Page tests (`@penmoss/android-editor`, 87): `focusTitle` puts the caret in the title, ignored for another note; the contract suite reads the new `focusTitle` fixture both ways, as does Kotlin's `BridgeProtocolTest`.
  - Full `task android:test` (690 JVM/Robolectric tests — 589 app, 101 engine-bridge — 0 failures; plus the editor page's 87), `task android:build`, `task typecheck`, `task lint` (ESLint, stylelint, Prettier), and the full server suite in workerd (39 files, 640 tests, 0 failures) — all green.

## Walk-through (by test, against the canned servers)

| Step | What happens |
| --- | --- |
| New folder | Home's ⋮ menu → **New folder** (top level), a folder's ⋮ menu → **New folder** (inside it), or a folder row's sheet → **New subfolder**: a name dialog (Save off while blank). The folder shows at once; offline too. The next pass sends `POST /api/folders` with this phone's ULID; a retry answers the folder it made. `changesMadeOfflineReachTheServerInOrder`, `aFolderMadeHereShowsAtOnceAndWaitsToBeSent`. |
| Rename | A folder row's sheet → **Rename**, or a folder's ⋮ menu → **Rename folder**: the dialog starts with the name. Sent with what was seen; a rename elsewhere since answers 409 and the phone drops it (`aRenameOvertakenOnTheWebIsDropped`). |
| Move | A folder row's sheet → **Move to…**, or a folder's ⋮ menu → **Move to…**: the T38 picker without the folder and its subfolders (self-moves refused at once, and by the server). A parent deleted meanwhile falls back to the top level (`aCreateUnderAParentDeletedMeanwhileFallsBackToTheTopLevel`, `aMoveToAFolderDeletedOnTheWebMeanwhileEndsAtTheTopLevel` for notes). |
| Delete | A folder row's sheet → **Delete**, or a folder's ⋮ menu → **Delete folder**: "N notes and M subfolders move to X" (or "The folder is empty"). Notes move up at once; subfolders go. A folder made and deleted before anything was sent never reaches the server; a create tried with no answer queues the delete instead, so the server's copy does not reappear (`aDeleteAfterATriedCreateQueuesADelete`). |
| Sort | The Sort icon in Home's and each folder's top bar: Manual, A–Z, Last modified as radio items with the current mode checked. Choosing queues the sort (last write wins, replacing the choice not sent yet). Reorder is offered only in a Manual folder. |
| Reorder | Overflow → **Reorder** (a Manual folder, or Home's manual top level): rows get drag handles; Done (or Back) ends it — the top bar's Back and the system Back both end the mode first, on Home and in a folder (T40 P4 review S6). A handle drag moves the row with a tick at each slot and sends one `place` intent on drop; TalkBack's Move up/down actions and Alt+↑/↓ send one at once. A folder's list shows Manual order (folders among folders, notes among notes); Home's top level reorders folders only (its notes list is Recent, by recency — the NT7 exclusion in A446); anything else keeps its own sort. |
| Rename from lists | The long-press sheet in every list gains **Rename** between Move to folder… and Move to Trash: the note opens with the caret in its title (`focusTitle`). |
| Breadcrumb | The note's top bar shows the folder path ("Projects › Penmoss", truncated from the start; "Top level" for an unfiled note). A tap opens the note's folder (Home for the top level, leaving the note behind); a long press lists every level. |
| Offline and sign-out | Every folder change waits in Room (schema 11, `folder_ops`), sent in order before the notes are filed; Sync and storage lists them. Sign-out keeps them (`unsentCount`). A tree read meanwhile lays them over what it reads; a change for a folder deleted on the web is dropped with a notice ("…was deleted on another device…"), one overtaken by a rename or move with its own ("…was renamed/moved on another device…" — T40 P4 review B2). A create tried with no answer that a delete meets queues the delete instead of cancelling both (T40 P4 review B3). |
| Older servers | Against a server from before these routes, creates, sorts, moves, reorders and deletes wait (dropped nothing); Sync and storage lists the folder changes until the server is updated (A449, `folderChangesWaitForAnOlderServer`). |

**Not walked through on a device:**

- **Drag handles with a finger** (NT7): the drop→intent path is covered by the custom-action tests (same `commit`), and the Pixel checklist drags a folder and a note by hand.
- **Alt+↑/↓ on a hardware keyboard**: the same `moveUpDown` path; covered by custom-action tests, checked by hand on the Pixel.
- **TalkBack announcements**: the row's place ("Folder, 2 of 5") and the live-region notices are in the checklist.

## Tests

- **Server (workerd):** `folders.test.ts` (22: all routes, preconditions, retry-after-applied, idempotency, reorder, scope refusals); `folder-scope.test.ts` (+4 route probes, the move probe carrying `place`).
- **Kotlin (`engine-bridge`):** `OrderKeysTest` (3 golden-vector and betweenness); `FolderTreeTest` (+3 `reorderKey`, anchors, end, invalid keys); `HttpPenmossApiTest` (+1 folder routes and `place`).
- **Robolectric (`app`):**
  - `FolderStoreTest` (15) through the real Room store: optimistic rows and queues, refusals, cancel-out, tried-create delete, coalescing, tree re-application, per-outcome notices, unsent counting.
  - `FolderSyncTest` (12) through the real coordinator, engine, store, senders and HTTP client against `FakePenmoss` (extended with folder routes, retry-safe preconditions, `place`, invalid-key-safe positions, a lost create reply, and a route-missing flag): ordering, filing after creates, 409/404 drops, applied-retry keeps later changes, tried create+delete, fallbacks, older servers.
  - `FolderScreensTest` (14): sheet, dialogs, sort menu, breadcrumb tap and levels, reorder handles and actions with anchors, Home and FolderScreen wiring, Back ending Reorder mode.
  - `ItemsTest` (+2), `MigrationTest` (+2 schema 9→10, schema 10→11), `TrashScreensTest` (Rename between Move and Trash).
- **Mutation checks:**

  | Change made to the code | What failed |
  | --- | --- |
  | `FolderSender` without `continue` after the create fallback | `aCreateUnderAParentDeletedMeanwhileFallsBackToTheTopLevel` (one POST, folder never at the top) |
  | `saveTree` without the pre-clear `reordered` snapshot | `anOldTreeKeepsWaitingChanges` (the tree's placement wins over the optimistic key) |
  | `reorderKey` without nearest-valid bounds | `reorderKeysTolerateKeysTheServerCouldNeverHaveMade` (throws on the phone's own optimistic keys) |
  | `sendPatch` dropping on any 404 | `folderChangesWaitForAnOlderServer` (older servers drop instead of waiting) |
  | `patchFolderEntry` without the already-applied escape | `answersARetryOfAnAppliedRename/MoveWithTheFolder` (a lost reply's retry 409s and drops later ops) |
  | `deleteFolder` cancelling a tried create | `aDeleteAfterATriedCreateQueuesADelete`, `aCreateTriedWithNoAnswerIsDeletedRatherThanCancelled` (the server's copy reappears) |
  | UI without the sheet's Rename item | `aLongPressSheetOffersMoveRenameAndTrash` |
  | Host without the `focusTitle` case | `contract.test.ts` "reads every message the app may send" |
