# T40 · Android parity matrix and plan

Step 1 of T40 ([issue #76](https://github.com/htxryan/penmoss/issues/76)): every capability of the web app and the Mac app, its state on Android, and a design for each gap. Audited on 24 Oct 2026 against `origin/main` at `2b9220b` (after T38, before T39's Android pass, which is in flight on `codex/t39-android`).

**Ryan's goal (24 Oct 2026):** "complete parity… You can do anything in the Android app that you can do in the main web app or Mac app. Settings, including all other functionality." Parity here means the same capability, adapted to a phone and touch, not the same layout.

**What was read.** Issue #76; the plan of the time (spec, FR table, T1–T38; removed 7 Nov 2026); `docs/decisions.md` (D1–D32, A1–A401); `docs/android.md`, `docs/desktop.md`, `docs/mcp.md`, `docs/cli.md`; the review files `android-review.md`, `android-editor-review.md`, `android-capture-review.md`, `android-bgsync-review.md` and `android-organise-review.md`; and the code:

- `apps/web/src`: routes (`router.ts`), every Settings section, the command registry (`commands/definitions.ts`), palette, switcher, cheat sheet, folder tree, tag pane, calendar, history, Trash, search and graph;
- `apps/desktop/src`: menus, IPC, deep links, hotkey, dock menu, updater;
- `apps/android`: every screen, the editor page (`editor/src/host.ts`, `protocol.ts`), the API client and the Room schema;
- `packages/editor`: `noteExtensions` and the services each extension needs, the slash catalogue, clipboard and paste.

## How to read the matrix

- **Android status:**
  - **Present:** works on Android today, possibly adapted to the phone.
  - **Partial:** some of it works.
  - **Missing:** not on Android.
  - **N/A:** not a capability of the web or Mac app either, or one that does not apply to a phone, with the reason given.
- **Mechanism**, in the design column:
  - **Native:** a Compose screen or control (Material 3).
  - **Bridge:** new editor-page messages in `contract/bridge-v1.json` (A300).
  - **Page:** a new APK asset page with its own contract, no network (A293's posture).
  - **Server API:** a new or changed route.
  - **Custom Tab:** the web app's own page in Chrome's Access session, as the Mac app's **Open in browser** does (A223). Since T41 (D34) admin screens are native instead.
- **Size:** S is under a day, M a few days, L about a week, for one agent with tests.
- **Slice:** the PR in the [implementation plan](#implementation-plan) below. A gap marked _adapt_ is designed differently from the web on purpose; the reason is in the row.

## Invariants every design keeps

These come from the decisions and the five Android reviews. A design that needs to break one is called out in its row and needs a decision.

1. **Kotlin never parses Yjs** (A11, A280; `NoYjsInKotlinTest`). Note content is read or written only by the editor page or by the server; Kotlin moves opaque base64 updates and server-minted state vectors.
2. **The WorkspaceDoc is never written by Kotlin.** Folders, the note registry and synced settings live in the WorkspaceDoc's Yjs. Kotlin reads them as JSON from `/sync/tree` (A281, A305) and changes them through **intent routes** the WorkspaceDoc runs with the shared `@penmoss/sync-client/workspace` functions (`createFolder`, `moveFolder`, `setSetting`, …). Offline, a Room queue holds the intent and the lists show it at once. A newer change elsewhere wins: each intent carries what it replaced, and the server answers 409, as moves do (A352, A359).
3. **Pages reach nothing** (A293). The editor page, and any new page (graph, theme preview), has no token, no `connect-src` and no navigation. Kotlin answers every request it makes and feeds it data over the message channel.
4. **The bridge grows by adding messages** to `bridge-v1.json`, and both suites check every message (A300). A new page gets its own contract file.
5. **Edits belong to their copy** (A291, A306, A309): pending edits carry their epoch, and conflict copies fail closed. Any new path that writes note content (periodic notes, Trash) goes through the page and these rules.
6. **Native admin passes the phone's own check** (D34, A503; amends A15, A223). The Mac app's sign-in through `/native-sign-in` carries `admin`; Android's does too since P2a, with its check (A420, A421; a token from before signs in again); CLI and agent tokens never do. Kotlin asks BiometricPrompt (`BIOMETRIC_STRONG or DEVICE_CREDENTIAL`, so the screen lock where no biometric is enrolled) before every admin change (core's `ADMIN_ACTIONS`: Delete for good, revoke a device or token, create a token, sign out everywhere, recovery code, approve a sign-in, Back up now, Clear errors) and sends nothing when it is refused. Admin reads need no check. In-app confirmations stay. A phone signed in before T41 holds a read-write token and is asked to sign in again before its first admin change. The editor page never holds a token (invariant 3).
7. **Folder-scoped tokens never sync** (A193). Device tokens are never folder-scoped, so the phone always sees the whole workspace.
8. **Nothing unsent is lost** (A345, A360). Every new queue (settings, folder changes, Trash, files) counts in `NoteStore.unsentCount`, survives sign-out, and is in `PassWork.anythingToSend`, so the leave-time background run sends it (T35).
9. **Background sync stays byte-moving** (A320–A331). No WebView runs in the background. Metered rules (A328) apply to any new download: plain text for search, remote pictures and files.
10. **Agents gain nothing they lacked.** Routes added for the phone (settings, folders, Trash) take device and browser principals. They refuse agent tokens unless an MCP tool already allows the same change. This answers the capture review's S2 concern about agents changing settings.
11. **D1 stays an index** (D6). Link, tag and text data sent to the phone from D1 is rebuildable and never the only copy.
12. **The Worker stays thin** (D20). New per-note work, such as plain text for search, runs in the NoteDoc, never in the Worker.

### Editor

The Android editor is the shared `@penmoss/editor` in a WebView, so every block and input rule comes for free. `apps/android/editor/src/host.ts` passes `noteExtensions` only `links` and `images`. Without `files`, `clipboard` and `foldState`, and without `body`, `watch` and `headings` on `links`, the features behind those services are missing or partial. The web's selection toolbar is hidden on the phone (A301), so its Copy as… and Turn into… need a home of their own.

## Implementation plan

Nine slices, in order of daily-use value, with Settings and Appearance first as Ryan asked. Each slice is one reviewed PR, or two when marked, and owns a block of ten decision ids. Each follows the repository's Definition of Done:

- `task check`, `task android:test` and `task android:build` green;
- Robolectric screen tests and sync tests for every new queue;
- contract files checked by both the page's vitest and Kotlin;
- server routes tested in workerd;
- a Pixel checklist added to `docs/android.md`, run by Ryan.

**Start after T39's Android PR merges** (it touches `PenmossRoot.kt`, `Screens.kt` and `NoteScreen.kt`). Every slice keeps the invariants above, and each server half deploys before its Pixel check, as T33–T38's did.
