# T40 P9 · Keyboard, shortcuts, launcher and accessibility on Android

Evidence for the ninth slice of T40 ([issue #76](https://github.com/htxryan/penmoss/issues/76)):

- Hardware-keyboard dispatch with the synced bindings (PL9): the editor page dispatches in a note, one native dispatcher everywhere else;
- Settings → Keyboard shortcuts (ST8) and Android's Meta+/ helper for the cheat sheet (FD8);
- `keys.*` on the settings channel (ST2): `/sync/tree` sends them and `PUT /api/settings` takes them;
- Launcher app shortcuts (PL3) and Quick capture inside the app (PL1);
- The accessibility pass (PL14);
- The P5 review's N4 (has-note marks on the period row) and N7 (a page error ends a waiting Today only when it is Today's);
- The final parity pass, after P6, P7, P8 and T42 merged: P6's key router folded into the dispatcher, every web command placed, T42's two Android gaps closed (Trash's deleted folders, NT25; Agent activity, AC11), and every matrix row checked;
- T39 pass 3's cross-app wording and Settings' order (A550–A554), logged in [`../../t39/pass3.md`](../../t39/pass3.md).

Decisions A490–A499 and A550–A554 are in [`decisions.md`](../../../decisions.md). No Room schema change (main is at 15, P6's).

## How it was run

- **No emulator** (the lane's rule, and no KVM on the worker). The Pixel checklist in [`docs/android.md`](../../../android.md#test-keyboard-launcher-shortcuts-and-accessibility-on-the-pixel-t40-p9) is for Ryan: a Bluetooth keyboard, the launcher, large text, TalkBack, Remove animations and the Accessibility Scanner.
- **What covers it instead:** Robolectric key-event, Compose semantics and `ShortcutManager` tests, the editor page's vitest with real `KeyboardEvent`s in happy-dom, contract files checked from both sides, and workerd tests of the server half.
- Full runs, each alone under the shared lock, after rebasing on main at #118 (`cd32702`, after T40 P6 at `66a8806`): `task check` (lint, typecheck and every package's tests: server 762, web 367, editor 497, editor page 203, and the rest), `task android:test` (1,089 JVM and Robolectric tests: 947 app, 142 engine-bridge; 0 failures) and `task android:build`: all green.

## Walk-through (by test)

| Step | What happens |
| --- | --- |
| A key on Home | Ctrl, Alt and F-key presses reach `AppCommands` from `MainActivity.dispatchKeyEvent` before the focused view; the first available global command bound to the combination runs what the screen's own button runs (`AppKeysTest.runsTheCommandBoundToAKeyFromHomeOrANote`, `AndroidCommandsTest.aCommandDoesWhatItsScreensButtonDoes`). Plain letters, Shift+letters, Enter, a key's release and lone modifiers are never taken (`…neverTakesAKeyThatTypesOrThatTheKeyboardsIMENeeds`). Nor is a press without Ctrl that types a character on the keyboard's layout: AltGr on a Polish or German keyboard, Alt's dead accents (`…altGrTypesOnAPolishLayoutAndNeverRunsAnAltShortcut`, `…altGrTypesOnAGermanLayoutEvenWhereTheUserBoundTheKey`, `…aDeadAccentPassesThroughToBeTyped`), nor Android's own editing and system keys (`…keysAndroidAndItsTextFieldsKeepAreNeverTaken`). A held key runs its command once (`…aHeldKeyRunsItsCommandOnceAndItsRepeatsAreTaken`). |
| A key in a note | The WebView has focus, so the native dispatcher stands aside (`…leavesTheKeysOfTheFocusedEditorToItsPage`). The page's dispatcher, given the user's bindings and the app's available commands by `keys`, runs editor commands in the editor and sends app commands back as `command`, which Kotlin runs only if it listed them; right Alt with a letter that the layout changes, or a dead key, is typing, and a repeat sends nothing (`keys.test.ts`, `NoteEditorControllerTest.givesThePageTheBindingsAndRunsOnlyTheCommandsItSent`). |
| Rebinding | `keys.<id>` from the synced settings replace the defaults; a binding the phone cannot use (types, AltGr, kept for editing) keeps the default (`AppKeysTest.theUsersBindingsReplaceTheDefaults`, `…aBindingTheWebWouldRefuseKeepsTheDefault`, `ShortcutsContractTest` usable cases). |
| Settings → Keyboard shortcuts | Areas and Android key names; search and its empty state; Change records from the keyboard; refusals, Android's own combinations and conflicts in the web's words, with Use it here instead; a combination that types on this keyboard, or uses Meta, is refused, and Back and the volume keys pass through; a command that does not run on Android yet says when it arrives and offers no keys; Remove and Reset without a keyboard; a synced clash listed; nothing changes before the first sync (`ShortcutsScreenTest`, 14). |
| Meta+/ | `onProvideKeyboardShortcuts` lists the commands available now, by area, with their first key; the editor's only while a note is open (`AppKeysTest.androidsShortcutHelperListsWhatRunsHere`). |
| The server half | `keys.*` sent by `/sync/tree` when well-formed, written by `PUT /api/settings` (rebind, `[]`, `null` to reset, a Mac binding stored as it is, each stored list sent and compared as it is, so a stale base is a 409 even for a binding this client would not use; a retry; 400 for a malformed list or base; at most 500 commands with their own keys; 403 `insufficient_scope` for an agent) (`settings-keys.test.ts`, `settings.test.ts`, `contract/settings-v1.json`). |
| Launcher | Capture, New note, Today and Search, then the two notes opened last (truncated titles, newest first); the notes' go on sign-out; each intent opens its place; an intent that did not come through the non-exported alias is ignored, and so is one Recents replays; a note's id goes through P7's `DeepLinkInbox` and its ULID check; an action waits until Home has settled (`LauncherShortcutsTest`, `AndroidCommandsTest.aLauncherShortcutRunsOnceTheScreensAreUp`). |
| Quick capture | Home's ⋮ → Quick capture, first (`ScreensTest.homeListsFoldersAndRecentNotesAndOpensThem`); Ctrl+Shift+K anywhere (`AndroidCommandsTest`). |
| Coverage | Every command in `shortcuts-v1.json` has its Android place, and every Native one is registered by a screen (`AndroidCommandsTest.everyWebCommandHasItsPlaceOnAndroid`, `…everyCommandAndroidRunsIsRegisteredByItsScreens`). |
| Accessibility | Every text colour at 4.5:1 on every surface it is drawn on (page, sidebar, dialogs, soft containers): built-in text unchanged, two light accents moved a little; a failing custom theme moved just past it, keeping its hue; the note's page sent the same colours (`ThemeContrastTest`); headings, long-press labels, 48 dp targets on Home and Keyboard shortcuts, no slides with animations removed (`AccessibilityTest`, `ShortcutsScreenTest.eachButtonIsAtLeastATouchTargetAndSaysWhatItChanges`). |
| N4 and N7 | Day and week chips with a note show a dot and say "has a note" (`JournalScreensTest.theDaysAndWeekThatHaveANoteAreMarked`); a waiting Today ends only on its own request's error, or after 20 seconds with no answer (`NoteEditorControllerTest.keepsWaitingThroughAnErrorThatIsNotItsRequests`, `…saysSoWhenThePageNeverAnswersToday`, `…aNoteMadeInTimeIsNotThenSaidToHaveFailed`, `host.test.ts`). |

**Not checked off a device:** the Bluetooth keyboard itself (Robolectric's key events stand in for it), the launcher's own rendering of the shortcuts, the recorder taking focus by itself in its dialog (Robolectric never gives a dialog's window focus, so the test focuses it as TalkBack would), TalkBack's speech, and text at 130% in the WebView. Each is a step of the Pixel checklist.

## Deploy

This slice has a server half: `/sync/tree` sends `keys.*` as stored and `PUT /api/settings` accepts them, compares each base with the stored list as it is, refuses a malformed base and caps the commands with their own keys at 500 (A491); and two new routes for Trash's folders, `GET /api/folders/trash` and `POST /api/folders/:id/restore` (A497). All additive, no D1 migration. **Deploy before the Pixel checklist**; an older server refuses a rebinding from the phone (400) and Settings shows it as refused.
