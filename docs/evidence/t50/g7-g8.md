**JGit.** `org.eclipse.jgit:org.eclipse.jgit` **7.8.0.202609011348-r**, the newest release (A870). JGit 7 needs Java 17 APIs that Android has had since API 33–34; the app is Android 17+ only (`minSdk` 37, A835), so the older 6.x line some Android apps pin is not needed. Its HTTP goes through `java.net` (no Apache client), no gc, no mmap, no system or user git config. `assembleDebug` packages it (no `META-INF` clashes).

**Schemas.** No Room migration: each git notebook has its own database at the current schema, **19**, and the next free number, **20**, stays unused (A880). No D1 migration (the next is still 0014). The bridge contract (`contract/bridge-v1.json`) is unchanged: the git pages have a contract of their own, `contract/git-engine-v1.json` (A873). Nothing touches production.

## What landed

- **Transport** (`engine-bridge`, `app.penmoss.engine.git`; A870, A871, A875, A879). `JGitTransport` behind the engine's `GitTransport` operations: a bare shallow clone in app files that deepens on demand; commits built on the fetched remote head with the `Penmoss-Writer` trailer and the phone's identity, pushed as a fast-forward, a rejection rebuilt (no merge, rebase or force); HTTPS with a token kept with the Keystore, or `file://` with the person's confirmation; no SSH. `insteadOf`, `pushInsteadOf` and `pushurl` are refused on fetch and push before a credential is offered, and remotes are compared as exact strings. Every sync is bounded with a sticky cancel.
- **The engine page** (`apps/android/editor/src/git/`, `git.html`; A872–A874, A876, A877). The same `@penmoss/git-notebook` engine as the Mac and the CLI, headless, on its own origin, over binary frames. Its `LocalServer` answers the routes the phone's `HttpPenmossApi` calls, so Room, the Senders, `SyncEngine`, the editor and every screen work on a git notebook unchanged (`LocalGitApi`). A guard page lets Kotlin check every commit against the head JGit read. What a fetch brought is delivered even when the push fails, and kept across process death.
- **Each notebook its own graph** (A880). Its own Room database, preferences, files and fixed local session; `GitNotebookActivity` hosts the app's own screens (Home, folders, notes, the editor, search, Trash, History, tags, the graph, Settings), so whatever the personal notes can do, a git notebook can, and nothing crosses sources.
- **Home and Settings** (A883). Home lists git notebooks as sections of their own; Settings → Git notebooks (after Notebooks; Appearance stays first) adds, removes, configures and shows status; `app.gitNotebooks` is Native. Without an account, the app opens on its git notebooks.
- **The Journal notebook** (A882). Today and This week open in it; a daily note created offline on two devices gets one template body (the engine's daily note, A827).
- **Background sync** (`GitBackground.kt`; A881). WorkManager every 15 minutes with network constraints (Wi-Fi only when every notebook is), Doze and standby buckets honoured, plus an expedited run soon after the app leaves with changes or a capture is stored. Settings shows the last run and the next.
- **Capture without a server** (A882). The share sheet, the tile, the widget and quick capture store into the Journal notebook's graph and its Inbox note, offline too; none goes to Penmoss's server.
- **What only the person does** (A877, A879, A884). Confirm private, Remove, Delete for good and History's restore run BiometricPrompt (device credential allowed) with Kotlin's words: the note's title from the branch, sanitised and bracketed. Remove says how many changes are lost; Restore saves the note as it is first. A purge whose confirmation ran out stops the sync until confirmed again on the phone that confirmed it; a mark never confirmed here offers Keep note. Agents, intents and anything outside the app's UI never confirm.
- **The Mac nits** (A885). The Touch ID words shorten a long path in its middle; `purgedFrom` is cleared once a purge lands.

## Found and fixed on the way

- **A page's refusal reached Kotlin as a bare "error".** `GitChannel` lost the code of a `GitRefusal` thrown in a handler, so `purge_unconfirmed` and `repository_public` read as a failure. The cross-engine test failed first.
- **Captures from the phone were refused by the page's server.** The phone's capture ids are UUIDs, as the Penmoss server takes them; the page took ULIDs only. It now takes the server's id pattern and derives the Inbox note's id from the capture id (`captureNoteId`), so a capture sent twice makes one note.
- **Keep note seemed to do nothing** until the next settle: the note is read back from the branch. The editor's test now checks after settle.
- **Remove's count of changes lost** said none when the notebook was not open; it now says only that any not pushed are lost.
- **The Mac's owner-check words in `git-notebooks.test.ts` expected the old end cut.** With A885 a long path is cut in its middle. The worker's short `/tmp` paths fit whole, so the tests passed there; the Mac runner's `/var/folders/…` path is long enough to be cut, and CI failed (PR #167, first run). The expectations that name a repository on this Mac (confirm again, Delete for good and Remove in `apps/desktop/test/unit/git-notebooks.test.ts`, confirm again in `apps/web/test/unit/git-sources.test.ts`) now use `fitWords`, and pass with a long `TMPDIR` on the worker too.
- **`eslint .` needs more than Node's default heap on the worker** (11 GB, a 2 GB default): it ran out of memory with this PR's files and with `NODE_OPTIONS=--max-old-space-size=5120` passes. The Mac runners have the memory; nothing changed in the lint config.

## Review fixes (PR #167 at fec4e446)

The review found no blockers; these are its should-fix and nit items, in one push. Each test failed before its fix unless it says otherwise.

- **S1: an answer to a dead page crashed its coroutine** (`GitChannel.answer`). A page killed while Kotlin still answered threw `IOException: Stream Closed` out of the call's coroutine: in the JVM tests it failed an unrelated test (`SettingsContractTest`, uncaught before the test), and in the app the hub's scope had no handler, so it would end the app. The send is caught and logged (`onLost`; the engine's goes to its log): the page is gone, and nothing else needs doing. The hub's scope has a `CoroutineExceptionHandler` beside its `SupervisorJob`. `GitChannelTest` kills a page while the app answers two calls: both answers are lost quietly and nothing reaches the scope's handler (failed first on the old send).

Now the page asks `navigator.storage.persist()` and says what it got, and before Room syncs with the new store each old copy goes to the page, which brings back what git lacks as "<title> (recovered)" (a copy, so no old client id is written again). Room's update strings go to the page as they are and the page decodes them, so Kotlin still reads no Yjs (A11; `NoYjsInKotlinTest` caught a first draft that decoded them in Kotlin). - **Nit 3: purge titles in Settings** are cleaned and isolated as the owner check names them (`OwnerWords.title`; `OwnerWordsTest`, `GitNotebooksScreenTest`), and `GitCrossEngineTest`'s comment is now checked.
- **Nit 4: the guard page has an origin of its own**, `https://git-guard.penmoss.invalid`, apart from the engines' (`GitPagesTest`).
- **Nit 5: a Delete for good whose prompt outlived the 120 s request** (A887). ## The last window closed (PR #167 at 87728d53)

A Delete for good that lands in the repository after the phone's last fetch could still be beaten by a recovery: the phone could not know of it, so the copy was made and pushed. Each test failed on the code before its fix.

- **A copy records where it came from.** `recover` writes `recoveredFrom` (copy id → original id) into the WorkspaceDoc, synced like `purgedFrom` (`@penmoss/git-notebook`'s `purge.ts`).
- **Dropped at the commit if its original was deleted for good** (replaced in the next section: such a copy is now withheld, never deleted, and only a purge from another device counts). Every sync, once it has merged the fetched head and before it builds the commit, drops a copy that has never reached the branch and whose original is deleted for good: out of the tree, its link with it, with nothing asked, since the person deleted the original (`engine.ts`, `racedCopies`). A copy already on the branch stays, its link kept, whatever later happens to the original. `git-page.test.ts`, "a Delete for good landing after the phone's last fetch drops the copy before its first push": the Mac deletes Passwords for good after the phone's last fetch; the phone brings back copies of it and of Groceries; its sync drops the first and pushes the second; nothing at head holds "hunter2"; and a later purge of Groceries leaves its pushed copy (before: the copy reached head).
- **Main refuses a commit that adds one.** `commitPurges` names the copies a commit adds whose original is deleted for good (`raced`); Android's guard page and the Mac's main refuse such a commit (`purge_raced`). `purge-check.test.ts` (a page script's copy is named; a copy pushed before the purge is not), `git-notebooks.test.ts` on the Mac (refused, then the engine drops the copy and nothing reaches the branch), `GitAskTimeTest.aCommitAddingACopyOfANoteDeletedForGoodIsRefused` on Android.

A copy is never matched by content: the head no longer holds a purged note's content, and a person may write the same text again on purpose.

## Withheld, never deleted (PR #167 at 62a3d621)

The delta check's blocker: that drop took the copy, and everything typed into it, whenever the original was deleted for good, a purge made on the phone itself included (the reviewer's probe: recover "Passwords NEWEDIT", type "TYPEDLATER" in the copy, delete the stale original for good, sync: both gone everywhere, nothing said), and the same when another device deleted the original while the phone was offline. Each test failed on the code before its fix.

- **Only a purge from another device counts.** `racedCopies` weighs the purges at the fetched head, never one made here: the person can see the copy and chose to delete only the original. The guard does the same: `commitPurges` names a copy as `raced` only when its original was deleted for good at head, never in the commit itself (`purge.ts`, `purge-check.ts`, `engine.ts`). `git-page.test.ts`, "a Delete for good of the original made on this phone pushes its copy, with what was typed on it (the probe)": the probe as the reviewer ran it, through the page, with a guard page as Android's; the copy and TYPEDLATER reach head. `purge-check.test.ts`: a copy whose original the same commit deletes is not named.
- **Withheld, never deleted.** A copy not yet pushed whose original another device deleted for good is withheld from the push: before it leaves the notebook, the page hands its whole doc to the app (`copy.withhold`), and Room keeps it aside as `WITHHELD` rows (state 7, the original's id in `copiedTo`), with its title on its note row, out of every list. Any other row of it joins them, so an edit typed after (the page answers Gone) never becomes a conflict copy, which would make a new note of it; a pass never retries them. Without a place to keep it the sync stops, nothing changed or pushed. Neither its logs nor its entry are committed; an upload to it is refused. Where the engine has no such hook (the Mac, the CLI), its own store keeps the doc (`withheld` in the replica's bookkeeping). `git-page.test.ts`, "a purge fetched from another device withholds the copy with its typing; Save their text has it all, and Keep and sync pushes it once confirmed"; `RoomOldCopiesTest.aWithheldCopyKeepsEveryRowWhatIsTypedAfterTooAndIsNeverRetriedNorMadeAConflictCopy` (failed first without either Room change); `GitTrustTest.aCopyWithheldFromThePushIsKeptAsideBeforeItLeavesTheNotebookOrTheSyncStops`; `purge.test.ts` for the engine's own store.
- **Said, with three ways out.** Settings → Git notebooks and the notebook's Sync say "A recovered copy of a note deleted for good on another device was kept on this device only." with its title, and offer **Save their text** (every row of it, the typing included, as markdown), **Delete for good** (the owner check naming the copy, then gone from the phone; git never had it) and **Keep and sync** (the owner check naming the copy; then it is back in the notebook, filed where it was, its link kept, and the next sync pushes it as a new note). Remove counts it among what it would lose. `GitNotebooksScreenTest.aCopyWithheldFromThePushIsSaidWithSaveTheirTextDeleteForGoodAndKeepAndSync` (new screen, so it could not fail first).
- **Main lets a kept copy through once.** `purge_raced` stays, except for a copy this phone's owner confirmed with Keep and sync: a confirmation bound to that copy, kept like a Delete for good's (10 minutes for a first commit to carry it, then until that commit lands), spent once its push lands. A commit adding another copy too is refused. If main refuses a kept copy anyway (its confirmation ran out), the engine withholds it again at the next sync, for the person. `GitAskTimeTest.keepAndSyncConfirmedLetsThatCopyThroughOnceAndNoOther` (failed first with the confirmation ignored).
- **An entry never lands without its log.** A copy not on the branch yet is always written with its entry, and a sync that could not write one stops (`copy_unwritten`); one whose content this device lacks leaves the tree first. `purge.test.ts`, "a copy's entry never lands without its own log".
- **The Mac.** The Mac never brings copies back, so no copy there is withheld but one a page script made; its main refuses that copy whatever (there is no Keep and sync to confirm one), and its engine keeps it in its own store (`git-notebooks.test.ts`).

## A note window's last keystrokes (PR #167 at 5cdaa525)

The Mac bug from G3–G6 (#166) that made `git-notebooks.spec.ts:405` flaky: a note window closed straight after typing lost its last keystrokes, so the main window's engine never pushed them. The check that showed it, the main window holding the whole tag after the close and the branch having it, is now part of the test.

- **What the loss was.** The test closed the window with Playwright's `close()`, which tears the page down with no `close` event on the window and no `pagehide` either (traced: a `pagehide` and a `visibilitychange` listener in the closing window never ran, and a reload of the main window showed the tail missing from IndexedDB too). So main's hand-off never ran (`storeBeforeClose`: it asks the window to store everything and waits up to 3 s, T29), and what the window had not stored yet, the last keystrokes, went with it. Closed the way a person closes it (⌘W or its button, `BrowserWindow.close()`), the hand-off runs, the main window reads what it stored and the engine pushes it: 6 of 6 on the code before this round.
- **The test closes it as a person does,** and checks the main window for the whole tag, then Sync now and the branch (the CLI's `cat`). It also checks the other way a window's last keystrokes can go: a window that goes without the hand-off (its 3 s ran out, or it was torn down) keeps them in local storage as it goes (`putOnUnload`, A626). Those were merged only when a store next opened, so the main window, open already, never took them in and its engine pushed nothing until the next launch. The test opens a third window, types, has it keep its keystrokes as it goes (`pagehide`), tears it down with Playwright's `close()`, and checks the main window and the branch for them. That part failed 6 of 6 on the code before the fix.
- **The fix.** Each open store merges such a change as soon as it is kept (`NoteStore.watchUnloadWrites`, on the `storage` event that the other windows of the origin get), not only at its next open. Its write listeners hear what it merged, so the window that holds the engine takes a git note's edits in and schedules a push, and `Notes` reads the records into what the window shows. What no window merges before the app quits stays in local storage, removed only once merged, so the next launch still takes it in; if the main window is closed too, the existing takeover applies. The capture window starts the same `Notes` service, so the same holds there; it closes only when the app quits, after the same hand-off, and hides otherwise, keeping its draft. `idb.test.ts`, "merges what another window keeps as it goes at once, while this one stays open"; `notes-service.test.ts`, "reads what the store merged from a window that went, as it is merged, until it stops" (failed first).
- **One change, one copy** (the final check at a1814373). Every open window hears the same entry, and one that cannot join its note (the note is gone, or of another epoch) becomes a conflict copy, which had a random id: two windows made two copies of one change, and a git notebook pushed both. The copy's id now comes from the entry's key and content (`unloadCopyId`, a ULID timed when the change was kept), and a window that finds that copy stored already leaves it, so windows that merge at once make one note. A Web Lock per store (`penmoss:unload-merge:<store>`) lets one window merge while the others wait and then find the entry gone. It only saves work: a window that dies holding it lets it go, and the entry is removed only once merged, as before. `idb.test.ts`, "makes one conflict copy when two windows merge one entry for a gone note", for the personal store and a git notebook's, with the lock and without it. Before either change, both stores' tests made 2 copies; with the lock but not the id, the two without the lock still did.
- **Repeated:** the signed-in test passed 20 of 20 (`--repeat-each=20`, no retries).
- **`capture.spec.ts:259`, not the same cause.** It failed at its first step, before any typing: after the hotkey press (xdotool on xvfb), the capture window did not show within 5 s (`openCapture`). `capture.spec.ts:161` failed once the same way, at the first press after a relaunch. Both presses came right after another Penmoss instance closed on the same display. Nothing is stored or lost there, and the draft is never involved. Not reproduced: `capture.spec.ts` passed 64 of 64 (`--repeat-each=8`) alone, and those two tests 12 of 12 with six busy loops on the four CPUs. Left as it is, with no change to the test.
