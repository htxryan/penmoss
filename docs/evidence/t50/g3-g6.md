## What landed

- **Main process** (`apps/desktop/src/git-notebooks.ts`, `git-processes.ts`; A853–A857). `penmoss:git:*` channels; a registry of this Mac's notebooks; bare partial clones under `userData/git-notebooks/`; tokens, writer secrets and confirmations sealed with `safeStorage`; the private check before every call that can reach the host; owner checks through Touch ID (`systemPreferences.promptTouchID`) or the password helper, with main's own words; every git killed on quit and on a signal, and any a crash left killed at the next launch.
- **The page** (`apps/web/src/sources/`; A851, A860, A862). A `GitSource` per notebook with its own store (`penmoss-git-<id>`), `Notes`, `Workspace` and link registry; one engine per notebook across windows (a Web Lock, A822) over an IPC transport, its status shared on a BroadcastChannel; the `Sources` registry (personal and git side by side, the Journal notebook, the server-less boot); `SourceScope`, so every view works in its note's source.
- **Views** (A826, A827, A862). Sidebar sections with their own tree, sync state and Trash; search across sources with labelled hits (words only in git notebooks); Quick open and ⌘E across sources; Move, History, Trash and the graph in the note's own source; the Journal notebook in Settings → Daily notes; the status bar in git's words; error reports redacted.
- **Settings → Git notebooks** (A855–A857): add, confirm private, token, cadence, signing, Sync now, status with the host's words, hand edits, Remove; View → Git notebooks.
- **History** (A858): the History panel reads a `HistorySource`, the server's REST or the notebook's commits; Restore and Revert edit the note here, as a change that syncs. The CLI's `history --notebook` and the local MCP's four history tools came in the lane's first commit.
- **G0's fixes**: "Syncing" no longer lasts for ever when the network drops (A859); backlinks reload on events (A861); no orphaned git (A853).
- **G1+G2's residuals**: actor files kept bounded without reusing client ids (A850), bounded CLI syncs with a sticky cancel (A852), the exact-remote hint (A854).

## Found and fixed on the way

- **Error reports were never sent after a sign-in** (A863). `ErrorReporter.flush()` with nothing waiting set itself as running inside its own assignment and never cleared it. The request-log check found it; `error-reporter.test.ts` failed first.
- **New note in a git notebook made nothing when pressed again quickly.** The repeated-press check looked the open note's title up in the personal list only. `git-notebooks.spec.ts` failed first against the old build.
- **A click in a section other than the one in use acted on that one.** The tree's buttons run tree commands, which the section in use answers; a pointer or focus in a section now makes it the one in use first.
- **Privacy stayed "You confirmed it" after a token showed GitHub says private**, until something else refreshed Settings: main now tells the windows when what it saw changes (`git-notebooks.test.ts` failed first).
- **The CLI test still expected 25 local MCP tools**; G6 made it 29.
- **A new note's title lost its focus to the Trash toast's Undo** after a note was trashed. The palette, Move and the toasts sit in the open note's source, and moving from no note to one mounted them again, so the toast took focus once more. `SourceScopeOr` keeps one tree with a source or without (`source-scope.test.tsx`); the Mac suite's "nothing that clicks drags the window" failed first.
- **The Mac suite's list of the bridge's keys** gained `git` (A853).
- **Unlinked mentions waited for the server's index** once backlinks stopped polling (A861): CI's web suite showed a mention made seconds before missing for 30 s. A note changed on this device in the last minute now gives its unlinked mentions from this device's copy, as its links already did (`links.test.ts` failed first).
- **Android's parity guard** wanted a place for the new `app.gitNotebooks` command. It is the one command planned for a later slice (`Coverage.Later`, G7 and G8, #155 and #156), and `AndroidCommandsTest` fails once a git notebooks screen exists while it is still not Native.

## Review fixes (PR #166 at 3041efa6)

Each test below failed before its fix, unless it says otherwise.

- **B1: notes pulled from git were lost when the push failed.** The engine now keeps what a fetch applied until the windows take it (`takeGitChanges`), and the host delivers it whatever the push did. `git-sources.test.ts`: the CLI renames a note and pushes, the Mac has an edit not pushed, its push fails once: the window shows the new title; the same for a note deleted for good.
- **B2: Undo on the Trash toast went to the wrong source.** The toast carries the source that trashed the note (`Trashed.from`), so Undo restores there, whichever note is open, and never asks the server about a git id. `git-notebooks.spec.ts`: signed in, a git note trashed from its section while a personal note is open, and from its own view; no account, a note trashed from a second notebook's section while the first's note is open; the request log holds none of their ids. Both failed against the old toast.
- **S1: Remove lost changes not pushed and said the repository kept everything.** Remove now asks the source what is not pushed: nothing, and it goes straight to Touch ID; something (or it cannot tell), and it says how many notes would be lost and offers **Push first**; **Remove anyway** asks Touch ID in words that say so (`git-notebooks.test.ts`, `git-notebooks.spec.ts`).
- **S2: History's Restore and Revert overwrote changes not saved as a version.** They first save the note as it is as a version (the Mac: store and push it; the local MCP: commit it), and refuse with 409 when they cannot (`history.test.ts`, `git-sources.test.ts`).
- **S3: taking a client id back corrupted a note** after a profile restore and a rewound branch (the reviewer's case, now in `client-ids.test.ts`). Reuse is off. A writer retires at 20,000 ids, and at once when its actor file would pass 1 MB (A850, and the re-review below).
- **S4: Delete for good was guarded only in the page.** Main now checks every commit: it may delete a note's files only once the owner check confirmed that note id, and the confirmation is spent once pushed (`purge-check.ts`; `git-notebooks.test.ts` drives the page's engine through main and is refused).
- **S5: a `file://` remote counted as private.** Penmoss cannot check a repository on this machine: it needs the owner's confirmation like another host (`visibility.test.ts`, `git-notebooks.test.ts`, the CLI's `notebook.test.ts`, `git-notebooks.spec.ts`).
- **S6: "Syncing" lasted while an open socket stalled.** The provider drops a socket that leaves the session or a probe unanswered for 15 s and counts a failed connect; the pill says Offline after two, until a socket syncs (`provider.test.ts`, A859).
- **S7: a cancel between git calls was lost.** The engine's sync takes a signal checked before each git call; the Mac waits for main's cancel to be confirmed; a push that landed after the time ran out shows as pushed; the CLI waits at most 5 s for a stopped sync (`engine-host.test.ts`, `notebook.test.ts`).
- **S8: an agent could confirm "private" through the CLI under `script -qec`.** Not fixed in code: anything the CLI could ask (a file, its credential store, a helper) a program running as the same user can also write or answer, so a Touch ID handoff would not be sound from the CLI. The docs and the PR now say what holds: agent clones and the MCP cannot confirm; a program running as you that makes itself a terminal or edits `~/.penmoss` can; the Mac app never takes the CLI's confirmation; on a machine where agents run as you, confirm in the Mac app (A855, [cli.md §8](../../cli.md#8-git-notebooks)).
- **S9: Push after and Pull every reached a running engine only at its next start.** They apply at once (`engine-host.test.ts`).
- **Nits.** The privacy cache is keyed by local id and remote; a push is refused (`redirected`) when git's config would send it elsewhere (`git-notebooks.test.ts`, with `pushInsteadOf`); leftover git is killed only if it also started when the one recorded did (`git-notebooks.test.ts`); a Touch ID prompt that times out keeps other checks from opening until it closes (`admin-check.test.ts`); backlinks list this device's recent mentions before the server's 50 and never count the open note as recent (`links.test.ts`); Remove's Touch ID words name the repository, never the notebook's name (`git-notebooks.test.ts`); `app.gitNotebooks` on Android is planned, not "not here".

## Re-review fixes (PR #166 at c29ba428)

Each test below failed before its fix, except A854's, which brings coverage back.

- **What a sync fetched was lost if its window went mid-sync.** It is now saved with the engine's state until the store holds it (`confirmDelivery`; A852). `git-sources.test.ts`: the CLI renames a note, the Mac's push hangs, window A stops, window B takes the engine over and shows the new title.
- **A slow link looped on reconnects.** The wait goes on while the socket's own upload drains (`bufferedAmount` going down), and a socket's first reply gets 60 s, more for a document the server sent large before (A859). `provider.test.ts` simulates a slow uplink and a slow downlink; neither drops the socket.
- **A854 over HTTP.** `notebook.test.ts` confirms `…/o/r.git` on a local `git http-backend` host and refuses `…/o/r` without a request to it; the signed-in Mac e2e now adds its notebook over HTTP from that host.
- **`actor_full` was a dead end.** A writer whose actor file at head, or with this sync's ids, would pass 1 MB retires at once and the sync goes on, its unpushed ids listed by the new writer (`client-ids.test.ts`).
- **Remove undercounted in a window that runs no engine.** It asks the engine's window, which reads every stored record first (`git-sources.test.ts`, with announcements that arrive late, as over IPC).
- **Fetches followed `insteadOf`, with the token.** Every git call that talks to the host checks git's fetch and push URLs first and refuses (`redirected`) before the token is handed over; a rewrite to SSH names the SSH remote to add (`node-transport.test.ts`, with two HTTP hosts; `git-notebooks.test.ts` refuses at Add).
- **Emptying another writer's log.** Main refuses a commit that replaces any log with less than the head holds (`purge-check.test.ts`, `git-notebooks.test.ts`).
- **Purge confirmations never expired.** They count for 10 minutes; a commit main let through keeps them until its push lands; Settings confirms again, once, for the notes still waiting, narrowed in the third review below (`git-notebooks.test.ts`).
- **The SSH rewrite UX** is in [desktop.md §6](../../desktop.md#6-git-notebooks) and [cli.md §8](../../cli.md#8-git-notebooks).

## Third review fixes (PR #166 at 138b53e3)

Each test below failed before its fix.

A second test checks the limit.
- **Confirming Delete for good again took every note marked in the notebook.** Main now confirms again only notes it holds as confirmed once, whose 10 minutes ran out, and refuses the whole list if one was never confirmed on this Mac. Settings first lists the notes by their titles, which main reads from the branch, and Touch ID gives the count and says they were confirmed once already (A855). `git-sources.test.ts` drives the button's path through the real main process. - **A retiring writer carried ids it had pushed.** When its actor file at head is too large for other clients, the writer still reads it, up to the 32 MB log limit, to tell which ids it lists. Only the rest go to the new writer (A850). `client-ids.test.ts`: an id used offline and never pushed is listed under the new writer, and none the old file lists.
- **A writer's own log too large to read was written over** with only what this device held, which main refuses as `log_shrunk` at every sync. The writer retires instead, and the new one writes its own log beside the old (A850). `client-ids.test.ts`: the old log is unchanged on the branch, and the edit reaches another device.

## Before merge (PR #166 at cd1a276f)

- **The first Delete for good named no note,** so a page script could ask Touch ID for any id. Main now reads the note's title from the branch and puts it in the prompt, quoted, with control, bidi, zero-width and quote characters taken out, and cut at 60 characters. The count and the title come before the path, so the 200-character cut trims only the path. A note main can't read is "an untitled note" with the end of its id; the page never supplies a name. `git-notebooks.test.ts`: a page script asks for another note's id, and the prompt names that note's real title; another test checks the cleaning and the cut. `git-sources.test.ts`: Delete for good… on a note never confirmed names it as the branch has it.
- **A purge never confirmed had no way out.** In Settings' list of those notes, each has **Keep note** and **Delete for good…**. Keep note takes the mark back and deletes nothing, so it asks for no Touch ID. The note is filed again at the top level, or stays in Trash if it was there, and Undo marks it again. Every engine reads back a note at head that it holds no copy of, so the note returns from the branch. `git-sources.test.ts`: a page script marks a note; Keep note, Undo, Keep note; the sync resumes with nobody asked, the note's logs on the branch are unchanged, its file is still there, and the window lists it again. `engine.test.ts` covers the engine's half.

## Before merge, second review (PR #166 at 3184815e)

- **A Delete for good that landed could be taken back.** The reviewer's probe: A purges "Secret" and it lands; B, with an old copy, edits it; A takes the mark back; B syncs and a fresh clone shows the text again. Now the main process refuses a commit whose merged workspace no longer holds a purge the head holds (`purge_reversed`, `purge-check.ts`). Engines set such a mark again, logging that the note is already deleted for good, and Keep note on a purge that landed says so and does nothing. Each test failed before the fix: `engine.test.ts` runs the probe, with no deleted text in a fresh clone or on the branch; `git-notebooks.test.ts` sends the page script's commit through main and is refused; `git-sources.test.ts` presses Keep after the purge landed.
- **Touch ID's words** name the repository first, then the note: its title in brackets, isolated (U+2068…U+2069) so right-to-left letters cannot reorder the words around it, with brackets and double-quote look-alikes (＂ ❞ 〞 ″ among them) taken out (`git-notebooks.test.ts`, with a title made to look like the words after it).
- **Keep note is undoable to the folder.** Marking a note deleted for good records where it was filed; Keep puts it back there (the top level if that folder is gone; in Trash if it was unfiled there), and Undo marks it again (`purge.test.ts`).
- **A dead link showed Syncing for up to the long first-reply wait.** Once the usual 15 s pass with no first reply, the pill says **Waiting for server**; the drop comes at the same time as before (`provider.test.ts`, `notes-service.test.ts`; A859).
