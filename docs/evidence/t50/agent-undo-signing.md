## 1. An agent's changes in a git notebook can be undone (A920)

- **Core** (`packages/git-notebook/src/agent-activity.ts`). An entry per commit whose `Penmoss-Writer` trailer names an agent and which touched `.penmoss/workspace/`; its change is the workspace merged from every writer's log at the commit against its parent, in the server's kinds and words (`folder.create`, `folder.rename`, `folder.move`, `folder.delete`, `note.move`, `settings`). Undo applies the server's inverses on a copy first, all or nothing, each only while things are as the agent left them (409 `changed_since`, "… Nothing was undone."), then on the live doc as the person's own change; the undo mark (`agentUndone`) syncs, so every clone shows who undid it. It never writes `purged`, never refiles a purged note, and `commitPurges` finds no reversed purge in the undo's commit.
- **Local REST** (`local/rest.ts`, `local/notebook.ts`): `GET /api/agent-activity` and `POST /api/agent-activity/:id/undo` in the server's shapes, so Android's Agent activity page and its routes are reused unchanged. An agent writer gets 403 `agent_not_allowed`.
- **Mac** (`apps/web/src/sources/GitAgentActivity.tsx` in Settings → Git notebooks): Agent activity per notebook, with the server's list component; Undo flushes and syncs at once.
- **Android**: the notebook's Sync → **Agent activity** opens the same screen over the notebook's local REST, with git's own intro and empty text.
- **CLI**: the CLI's `--notebook` commands are the agent's side; its help for `rmdir` and `retag` now says where they are undone (the apps' Agent activity; tag renames, an edit of each note, in each note's History). There is no `penmoss undo` for server workspaces either, so none was added.
- **Note edits** stay with History: `packages/git-notebook/test/history.test.ts` "reverts just the agent's edit, keeping the later human edit" covers an agent writer's edit, and Agent activity's text says so.

## 2. Android signs its commits (A921)

`SshCommitSigner` (`apps/android/engine-bridge`) writes the SSH signature `git` writes with `gpg.format=ssh` (`PROTOCOL.sshsig`, namespace `git`, SHA-512) into the commit's `gpgsig` header, checking it against the public key before the commit is inserted. `KeystoreCommitKeys` (`apps/android/app`) makes a non-exportable ECDSA P-256 key in the Android Keystore. Settings → Git notebooks has **Sign commits** per notebook and **Signing key** with Copy and Make a new key. With signing on, any failure throws `GitErrorCode.SIGNING`, "Sync stopped: signing. …", and no commit is made.

Why generated and not imported: no private key ever passes through the app, a file or the clipboard; OpenSSH's key files are usually locked with bcrypt_pbkdf, which neither Android nor the JDK has; and GitHub takes a key per device. P-256 by default, since every Keystore has it; **Make an Ed25519 key** (after the review) makes an `ssh-ed25519` key where the device's KeyMint has Ed25519, and leaves the old key where it does not. No new library: JGit 7.8 core has no SSH signer, and the MINA one would bring its key handling into the app.

## 3. The flaky cleanup (A922)

`git-sources.test.ts`'s `rmSync` raced a sync still writing (ENOTEMPTY). `GitSource.halt()` resolves once the running sync and its git calls have ended; the test's cleanups run last-first and are awaited. Audit of the other git tests: `packages/git-notebook` tests await engines and transports in memory or in their own temp folders; the CLI's `notebook.test.ts` detached-sync test now waits for the detached process to exit before its folder goes; the Electron spec quits the app (which kills every git, A853) before its folder goes; the JVM tests use `TemporaryFolder` after each synchronous call returns.
