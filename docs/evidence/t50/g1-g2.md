## What landed

- **The mirror's code is shared (A832).** `apps/server/src/mirror/{paths,tree,workspace-tree}.ts` moved to `@penmoss/core/mirror`, `do/markdown.ts` to `@penmoss/editor/markdown` and `agents/edit-engine.ts` to `@penmoss/editor/edit-engine` (`git mv`, so history follows). The server imports them from there. The server mirror's output is byte-identical: `apps/server/test/mirror-default-paths.test.ts` passes unchanged, and `packages/git-notebook/test/mirror-golden.test.ts` replays a corpus recorded from the server's own modules before the move.
- **`@penmoss/git-notebook` (A836).** The engine: the layout, writer secret, replica, own files, deterministic render with stored names, purge, actor files and the sync cycle over a `GitTransport`. `MemoryTransport` runs it without git; `NotebookOps` gives the note and folder operations; `/local` the REST and MCP equivalents; `/node` the system-git transport, the state on disk, the lock and the visibility check.
- **The CLI (A839–A843, A848, A849).** `penmoss notebook add/ls/sync/status/remove/token`, `--notebook` and `--no-sync` on 18 note commands, credentials and clones under `~/.penmoss/`, one lock per clone, and `git gc --auto` after syncs. See [`docs/cli.md` §8](../../cli.md#8-git-notebooks).
- **The local MCP (A830, A844, A845, A847).** `penmoss mcp --notebook <name>` over stdio: 25 tools with the remote server's names and schemas, from definitions now shared in `@penmoss/core/mcp`. The server's `tools/list` is byte-identical after the move (a fixture, key order included).
- **The #141 nit.** `withUnloadWrite` keeps the write's `seeded` flag (`seeded: write.seeded || stored.seeded`), with `packages/sync-client/test/unload-seeded.test.ts`.

Found while checking the fixes:

- **Piped MCP requests got no reply.** readline starts reading stdin when it is made, and the server only began iterating after its first `await`, so lines (and stdin's end) that came at once were dropped and the server waited forever. `lines()` now buffers from the start; `notebook.test.ts` pipes three requests into the bundled server.

## Design choices and deviations

- **No working tree, so no sparse cone (A837).** #150 says "a partial clone with a sparse cone for a directory". The clone is bare: the engine never reads a checkout, so it lists trees limited to `<dir>`, fetches only the missing blobs it reads, and commits through a temporary index. The effect the cone was for (fetching only the notebook) holds, with nothing to keep in step.
- **One writer per clone (A840).** An agent gets its own clone with `--agent`, rather than one clone serving a device and agents, so History can tell them apart and each writer's files stay its own.
- **Base versions are local (A843).** A note's `baseVersion` is the replica's revision, kept with the clone. The current one is always accepted; an older one is checked only by the process that read it (the last 8 per note), and from any other, 409 `base_unknown` asks the caller to read again. The server's versions don't exist without the server.
- **Keyword search only (A843, A826).** Hybrid falls back to words with a notice; semantic is refused.
- **Absent tools (A844).** History, versions and comments (G6 and later) are not listed; a call says why.
- **Settings (A827).** Only the notebook's `timeZone`, `template.daily` and `template.weekly`.
- **`summarise` moved to `@penmoss/core/diff`**, and the MCP definitions to `@penmoss/core/mcp`, so both servers share them (A843, A844).
- **An actor file alone never commits (A846)**, so a reader or a joining device makes no commit.
- **The MCP server holds the lock per call (A845)** and reloads when another process changed the state, so the CLI works alongside it.
- **A signal stop hands the push to a detached sync (A847)**, found in the Claude Code check.
- **Commit author.** As #147 says, commits carry the device's git identity, so the agent clone's commits are authored "Ryan Henderson" on the worker; the agent is named through its actor file (A829). Where git has no identity, the writer's label is used.
