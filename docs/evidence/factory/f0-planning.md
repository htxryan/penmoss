# F0.5 spike: the planning conversation

7 Nov 2026, Claude Code 2.1.318 and `@anthropic-ai/claude-agent-sdk` 0.3.318 on this Mac. The question: can one factory planning session hold the conversation on all three channels (artifact comments, issue comments, a direct chat) and publish the plan and the design itself? These runs used Ryan's own Claude login, outside the Seatbelt sandbox. The same runs with the factory's `CLAUDE_CODE_OAUTH_TOKEN`, inside the sandbox, wait on that token (see F0.4).

**Status: all three channels and both artifact kinds work, from one background session. What remains is the same runs with the factory's token, inside the sandbox.**

## What this means for the design

- **The planning session is a background session** (`claude --bg --remote-control`), not `claude -p` and not the Agent SDK. Of the three, only a background session got both a live artifact watch and Remote Control.
- **Issue comments reach it by stop and resume.** Stopping is also how Blocked pauses it (R23): while Blocked, the session isn't running, so neither it nor a chat can act. When Ryan clears Blocked, the dispatcher resumes the session with every comment since it stopped. The cost is that the chat link changes on each resume. The dispatcher posts the current link on the issue each time (with the session named after the issue, it is also easy to find in the app).
- **Settings for each planning session:** `--no-chrome` (otherwise Chrome control loads), `--strict-mcp-config` with no servers, project settings only, `dontAsk` with path-scoped `Read`/`Edit` rules, and the worktree marked trusted before the first start.
- **Interrupts pause auto-replies.** If a chat message or a resume interrupts a turn, comment auto-replies wait for the next message or republish. Stop and resume should therefore happen between turns, and the resume prompt should tell the session to read the artifact's comments (ArtifactComments, action "read").
- **Not yet known:** whether all this works inside the Seatbelt sandbox with the factory's token. A background session runs under the Claude Code daemon, not under `sandbox.exec()`, so it may need its own sandbox wrapper or may have to run outside the sandbox with read-only access. That check comes once the token exists.
