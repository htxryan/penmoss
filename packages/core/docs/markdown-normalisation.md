# Markdown normalisation

`serializeMarkdown` writes one canonical form of Obsidian-flavoured markdown. Parsing any markdown and serialising it gives that form, and serialising the result again changes nothing (byte for byte). This page lists every rule. Each rule names the fixtures in [`test/fixtures/`](../test/fixtures/) that pin it: `<name>.md` is the input and `<name>.expected.md`, when present, is the normalised output. `test/markdown-fixtures.test.ts` checks that every fixture named here exists and that every `.expected.md` fixture is named here, so no normalisation goes undocumented.

The dialect is CommonMark plus GFM tables, task lists, `~~strikethrough~~` and footnotes, YAML frontmatter, `$math$`, and Obsidian wikilinks, embeds, `==highlights==` and callouts. GFM autolink literals are off: bare URLs stay text (see [ADR 0002](../../../docs/adr/0002-markdown-codec.md)).

## Files

1. **Line endings and encoding.** Output uses `\n` line endings, has no byte-order mark, and ends with exactly one newline. An empty note is an empty file. Fixtures: `trailing-newline.md`, `empty.md` (CRLF and BOM input are covered by unit tests).
2. **Frontmatter** sits between `---` fences at the top. Frontmatter the app has not changed is written back byte for byte, comments and quoting included; invalid YAML is kept verbatim. Edited frontmatter is re-printed by the `yaml` Document API: key order, comments and unknown keys stay, lists are flow style (`[a, b]`) and long values are not wrapped. One blank line separates frontmatter from the body. Fixtures: `frontmatter-note.md`, `frontmatter-unknown-keys.md`, `frontmatter-only.md`, `kitchen-sink.md`.
3. **Blank lines.** Exactly one blank line separates top-level blocks; longer runs collapse, and a block that was written straight after a paragraph gets a blank line before it. Fixture: `blank-lines.md`.

## Text blocks

4. **Paragraphs.** Soft line breaks are kept (Obsidian shows them as line breaks). Spaces and tabs at the start or end of a paragraph, heading or table cell are dropped, because markdown cannot keep them. Empty paragraphs are dropped. Fixture: `paragraphs.md`.
5. **Hard breaks** are a backslash at the end of the line. Two trailing spaces become a backslash. Hard breaks at the start or end of a paragraph are dropped; inside a table cell a hard break is `<br>`. A `<br>` tag between text in a paragraph is read as a hard break (spaces and tabs beside it are dropped) and written as a backslash; at the start or end of a paragraph, or in a heading, where markdown has no hard break, it stays raw inline markdown. Fixtures: `hard-breaks.md`, `tables.md`, `html-ish.md`.
6. **Headings** are ATX (`#` to `######`) without closing hashes; setext headings are converted. Headings are one line: soft line breaks in them become spaces. Fixtures: `headings.md`, `headings-setext.md`.
7. **Horizontal rules** are `---`, except a rule that is the first block of a note without frontmatter is written `***` so it is not read as a frontmatter fence. Fixture: `horizontal-rules.md`.

## Inline formatting

8. **Emphasis.** Italic is `*x*`, bold `**x**`, bold italic `***x***`; underscore forms are converted. Strikethrough is `~~x~~` (a single `~` is never strikethrough), highlight `==x==`, inline code uses backticks (a longer run when the code contains backticks; line breaks in inline code become spaces). Spaces at the edge of a span move outside its markers (`** a**` would not parse). Where `*` cannot open or close (next to punctuation), the serialiser may fall back to `_` or write the neighbouring character as a reference such as `&#x61;`. Fixtures: `marks.md`, `marks-underscore.md`.
9. **Links** are inline: `[text](url "title")`. A destination with spaces is wrapped in `<…>`; parentheses in a destination are escaped. A link whose text equals its URL is written as an autolink `<url>`. Bare URLs stay plain text. Fixtures: `links.md`, `links-edge-cases.md`, `bare-urls.md`.
10. **Wikilinks** are `[[Title]]`, `[[Title#Heading]]` and `[[Title|alias]]`. A resolved link is written with the target note's current title (or its path when the title is ambiguous), so renames update links; an unresolved link keeps the text it was written with. A backslash escapes `[`, `]` and `|` in the target, heading and alias, and `#` in the target, so titles such as `C# notes`, `a|b` or `Q3 [draft]` survive: `[[C\# notes]]`. A backslash is itself escaped (`\\`) only before one of `\ [ ] | #` or at the end of a part; before any other character it is literal (`[[C:\Users]]`). Outside a table, `\|` is a literal pipe. Inside table cells every `|` takes one more backslash and the backslashes right before it are doubled, so the alias separator is written `\|` and a literal pipe `\\\|`. Fixtures: `wikilinks.md`, `wikilinks-escaped.md`, `tables.md`.
11. **Images** are `![alt](src)`, with Obsidian's size suffix `![alt|300](src)` or `![alt|300x200](src)` and an optional title. Fixture: `images.md`.
12. **Attachments** are links into an `attachments/` folder: `[report.pdf](../attachments/<hash>.pdf)`, relative to the note. Fixture: `attachments.md`.
13. **Math.** Inline math is `$…$` and block math is a `$$` fence. Two formulas with nothing between them cannot be told apart in markdown, so they merge into one with a space between (TeX ignores it). Fixture: `math.md`. In a table cell, a pipe in inline math is written `\|` (the run of backslashes before it is doubled and one added, as for wikilinks), because GFM splits the row into cells before reading `$…$`; reading undoes it, so `$|x|$` in a cell is stored `$\|x\|$` and LaTeX's `\|` is `\\\|`. Fixture: `blocks-tables.md`.
14. **Escaping.** A character is escaped with a backslash only where it would otherwise be read as markup: `*`, `[`, `` ` ``, `$`, `<` before a tag or autolink (including an email autolink that would run on into the next spans, as in ``\<`@a>` ``; a `<` before a span that cannot complete `<local@domain>`, as in ``List<`T` ``, is left alone), `_` at a word boundary, `==` where it could open or close a highlight, `~~`, and block markers at the start of a line (`# `, `- `, `+ `, `> `, `1. `). Ordinary prose is left alone: `#tag` at a line start, `AT&T`, a single `~`, `a == b`, `snake_case`. A literal backslash before whitespace, or before the last character of a text run, is written `\\`. Every `$` in text is escaped because single-dollar math is on. A paragraph that starts with `[label]:` would be read as a link reference definition, and inline code and math cannot escape their brackets, so in a link at the start of a paragraph each `]` in code or math that is directly followed by `:` is written as escaped text between two spans: ``[\]`:a`](url)``, not ``[`]:a`](url)`` (issue #44). Fixtures: `escaping.md`, `tags.md`, `html-ish.md`, `unicode.md`, `link-definition-guard.md`, `angle-brackets-before-spans.md`.

## Containers

15. **Bullet lists** use `-`. A list directly after another list uses `*`, so the two stay separate lists. Content is indented to the marker width plus one space. Fixtures: `bullet-lists.md`, `bullet-markers.md`.
16. **Ordered lists** use `.` and count up from the list's start number. Fixtures: `ordered-lists.md`, `ordered-paren.md`.
17. **Tight and loose lists.** A list keeps the tightness it was written with. A tight list is written loose (blank lines between items and blocks) when an item holds blocks that need a blank line to stay apart: a second paragraph, a table, a rule, a block after a nested list, or two quotes in a row. Fixtures: `loose-lists.md`, `nested-blocks-in-lists.md`, `nested-blocks-loose.md`, `code-in-lists.md`.
18. **Checklists** are `- [ ]` and `- [x]`, nested freely. A bullet list that mixes task items and plain items has no single node type, so each run of task items becomes a task list and each run of plain items a bullet list, side by side (A157); they are written apart, separated by a blank line, with alternating bullets (`-`, then `*`) so they read back as the same lists. An ordered list with task items (there is no ordered task list) is kept verbatim as raw markdown. Fixtures: `checklists.md`, `checklist-mixed.md`.
19. **Code blocks** are always fenced with backticks; indented code and `~~~` fences are converted. The info string's language and meta (`python title="x.py"`) are kept. Mermaid diagrams are code blocks with the `mermaid` language. Fixtures: `code-blocks.md`, `code-tilde.md`, `code-indented.md`, `mermaid.md`.
20. **Blockquotes** prefix each line with `> ` (a bare `>` on blank lines). Fixture: `blockquotes.md`.
21. **Callouts** are `> [!type] Title`, with `-` (collapsed) or `+` (expanded) after the type for toggles. A type is one word: whitespace and `]` in it become `-` (`my type` is written `my-type`), and an empty type is written `note`. The title is kept as written. The body starts on the next line when it begins with a paragraph, list, code block, math block, heading or quote; otherwise a bare `>` line separates it. Fixtures: `callouts.md`, `callouts-foldable.md`, `callout-nesting.md`, `daily-note.md`.
22. **Tables** are GFM with one space of padding and no column alignment: `| a | b |`. The delimiter row is `-`, `:-`, `-:` or `:-:`. Rows are padded with empty cells or truncated to the header's width, as GFM renders them. A `|` in cell content is escaped. Fixtures: `tables.md`, `tables-padded.md`, `tables-ragged.md`.
23. **Embeds** are `![[Title#Heading]]` on a line of their own. Fixture: `embeds.md`.

## Preserved syntax

24. **Raw markdown.** Syntax the document model does not represent is kept verbatim: HTML blocks and comments, footnotes, reference definitions and reference links, ordered lists with task items, inline HTML (except `<br>` between text, rule 5), inline embeds, links with empty text, and Obsidian's `%%comments%%` and `^block-ids` (which are plain text). Top-level raw blocks are byte for byte; raw blocks nested in a container are re-serialised from the syntax tree. Each raw block is separated from its neighbours by a blank line. Fixtures: `html-ish.md`, `footnotes.md`, `reference-links.md`, `obsidian-extras.md`, `links-edge-cases.md`, `embeds.md`.

## Known limitations

- Inline code inside a table cell cannot contain a backslash directly before `|`: GFM reads `\\|` there as a column divider.
- Image alt text ending in `|` plus digits is read as a size suffix.
- `$` in text is always escaped (`\$5`), because `$…$` is inline math.
